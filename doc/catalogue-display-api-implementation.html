POST /v1/catalogue/display

目录节点显隐与级联隐藏

管理员关闭一个正在显示的节点时，该节点和它的全部后代在同一事务中变为隐藏。重新打开它，只显示选中的节点。后代保留各自的状态，待排序的文件或文件夹仍须先排序才能显示。

前端设计第 ⑤ 项（旧版单节点规则） · 同级排序的显隐规则 · 目录树接口

传入节点 ID 和目标状态

使用 POST /v1/catalogue/display，请求头为 Content-Type: application/json 和 Authorization: Bearer <access_token>。catalogue.id 取自目录树，根节点也传它自己的正数 ID。根节点的 parent_id 才是 0。书籍归属与当前序号由后端查询。

请求 JSON隐藏第 1 章 
{
  "catalogue": {
    "id": "2123684178049376256",
    "display_status": "hidden"
  }
}
HTTP 200显示状态已生效 
{
  "code": 200,
  "message": "success",
  "data": {}
}

假设第一章当前可见、序号为 2，章内有已显示的正文和待排序的附录。本次请求成功后，第一章、正文和附录全部隐藏，各自的序号保持原值。用同一个 ID 发送 "display_status": "visible"，只会重新显示第一章。

隐藏请求成功后，前端用 POST /v1/catalogue/tree 重新读取当前书并刷新子树开关。成功响应的 data 为空，客户端无法据此区分实际切换和重复提交。显示成功时可直接更新选中节点的开关。若请求超时或响应丢失，也先读取目录树确认结果。

按锁定后的状态决定更新范围

当前 → 请求选中节点同书后代
visible → hidden设为隐藏。沿 parent_id 遍历所有层级，全部设为隐藏。遇到已经隐藏的中间目录也要继续向下。
hidden → visible排序校验通过后设为显示。保留每个后代的现状，包括已排序和待排序的后代。
hidden → hidden校验后返回成功。跳过遍历和写入。若管理员后来单独显示了某个已排子节点，重复隐藏父节点会保留该子节点的选择。
visible → visible排序校验通过后返回成功。跳过遍历和写入。

显示的前提。根文件夹使用 parent_id=0 和 sort=0；普通文件夹和文件须有正数序号。请求显示 sort=NULL 的普通节点时返回 20303。隐藏允许待排序节点保留 NULL，服务端也会校验直接发送的请求。

级联的边界。隐藏根节点会覆盖这本书根下的整棵树；隐藏叶节点只影响它自己。操作只写指定范围内的 catalogue.display_status，所有序号、祖先、兄弟分支、其他书的节点和书籍本身的显隐均保留。排序接口仍按自己的规则更新直接子项，例如将待排项排入阅读顺序时可以将它设为显示。排序时的状态转换。

把显隐规则放在 biz.Catalogue 中

在现有 biz.Catalogue.Display 的错误映射中，将 model.CatalogueCycleErr 与 model.CatalogueOwnerChangedErr 一并映射为内部错误。Display 接收完整的 *reqCatalogue.DisplayReq，由 DAO 取得行锁后调用 checkDisplayTarget 校验选中节点。当前目录业务实体。

复用 validateCatalogueRow 检查应用目标状态后的节点。传入的是行值副本，替换副本的 DisplayStatus 不影响 DAO 比较原值。先判断“普通待排节点请求显示”，再判断是否已经是目标状态。这样即使存量数据里有待排但可见的异常行，也不会误报显示成功；设为隐藏可以恢复它。根的类型或序号损坏、普通节点使用 0 等结构异常归为内部错误。现有的行校验。

// Display 在完整请求的基础上设置节点状态, 由控制器组装成功响应.
func (c *Catalogue) Display(ctx context.Context, req *reqCatalogue.DisplayReq) error {
	if c == nil {
		return &sys_error.InternalError{Cause: errors.New("biz.Catalogue.Display: nil receiver")}
	}
	if ctx == nil {
		return &sys_error.InternalError{Cause: errors.New("biz.Catalogue.Display: nil context")}
	}
	if req == nil {
		return &sys_error.InternalError{Cause: errors.New("biz.Catalogue.Display: nil request")}
	}
	if req.Catalogue == nil {
		return &sys_error.InternalError{Cause: errors.New("biz.Catalogue.Display: nil catalogue")}
	}

	orm := &model.Catalogue{ID: req.Catalogue.ID, DisplayStatus: req.Catalogue.DisplayStatus}
	err := orm.SetDisplayStatus(ctx, c.checkDisplayTarget)
	var internalErr *sys_error.InternalError
	switch {
	case err == nil:
		return nil
	case errors.Is(err, model.CatalogueNotFoundErr):
		return sys_error.CatalogueNotFoundErr
	case errors.Is(err, model.BookNotFoundErr):
		return sys_error.BookNotFoundErr
	case errors.Is(err, sys_error.CatalogueSortRequiredErr), errors.As(err, &internalErr):
		return err
	case errors.Is(err, model.CatalogueOwnerChangedErr), errors.Is(err, model.CatalogueCycleErr):
		return &sys_error.InternalError{Cause: err}
	default:
		return &sys_error.DatabaseError{Cause: err}
	}
}

// checkDisplayTarget 用锁定行的副本校验目标状态, 保留 DAO 中用于幂等判断的原值.
func (c *Catalogue) checkDisplayTarget(node model.Catalogue, target string) error {
	if node.ParentID != 0 && node.Sort == nil && target == enum.DisplayVisible {
		return sys_error.CatalogueSortRequiredErr
	}
	node.DisplayStatus = target
	err := validateCatalogueRow(&node)
	if err != nil {
		return &sys_error.InternalError{Cause: err}
	}
	return nil
}

在同一事务中隐藏目标和全部后代

在 model/catalogue.go 的错误定义处增加 CatalogueCycleErr，替换现有 SetDisplayStatus，并在同文件加入 (*Catalogue).hideDescendants。示例所需的导入和 CatalogueOwnerChangedErr 已在文件中。现有目录模型与排序事务。

  1. 按节点 ID 预读 book_id。开启事务后，按现有排序接口的顺序锁定书籍行和目标节点，复核归属再校验目标状态。同书的显隐和排序请求在书籍行锁上串行。归属变化时回滚并返回 500，每个请求最多开启一次写事务。
  2. 在锁内比较当前值和请求值。合法的同值请求直接提交。实际切换时先更新目标行并核对影响一行。只有原值为 visible 且目标为 hidden 才进入后代遍历，重新显示可直接提交。
  3. 从选中节点的 ID 开始，每批取最多 256 个父 ID，在本书内按 parent_id 锁定读取所有直接子节点。发现子节点时不按显隐或序号筛选，全部加入队列；写入时才跳过已隐藏的行。一个隐藏目录下的可见孙节点也会被找到。
  4. 队列为空后提交一次。批次大小只限制单条查询中父 ID 的个数。若查询或写入失败，或遍历时重复遇到同一 ID（父子关系成环），返回错误，回滚目标和先前所有批次的修改。
替换模型方法，新增错误与遍历方法model/catalogue.go 
// CatalogueCycleErr 表示沿父子关系遍历时再次遇到了已访问的节点.
var CatalogueCycleErr = errors.New("cycle in catalogue subtree")

// SetDisplayStatus 在一个事务中设置节点显隐, 从显示切为隐藏时同步隐藏全部后代.
func (c *Catalogue) SetDisplayStatus(ctx context.Context, check func(Catalogue, string) error) error {
	if c == nil {
		return errors.New("model.Catalogue.SetDisplayStatus: nil receiver")
	}
	if ctx == nil {
		return errors.New("model.Catalogue.SetDisplayStatus: nil context")
	}
	if check == nil {
		return errors.New("model.Catalogue.SetDisplayStatus: missing display rule")
	}
	if db.DB == nil {
		return errors.New("database is not initialized")
	}
	conn := db.DB.WithContext(ctx)
	var hint Catalogue
	err := conn.Select("book_id").Where("id = ?", c.ID).Take(&hint).Error
	if errors.Is(err, gorm.ErrRecordNotFound) {
		return CatalogueNotFoundErr
	}
	if err != nil {
		return err
	}

	tx := conn.Begin(&sql.TxOptions{Isolation: sql.LevelRepeatableRead})
	if tx.Error != nil {
		return tx.Error
	}
	defer tx.Rollback()

	lock := clause.Locking{Strength: "UPDATE"}
	var book Book
	bookErr := tx.Clauses(lock).Select("id").Where("id = ?", hint.BookID).Take(&book).Error
	if bookErr != nil && !errors.Is(bookErr, gorm.ErrRecordNotFound) {
		return bookErr
	}

	// 即使书已消失, 也要区分节点一起被删除和节点仍在但引用已失效.
	var node Catalogue
	err = tx.Clauses(lock).Select("id", "book_id", "parent_id", "type", "sort", "display_status").
		Where("id = ?", c.ID).Take(&node).Error
	if errors.Is(err, gorm.ErrRecordNotFound) {
		return CatalogueNotFoundErr
	}
	if err != nil {
		return err
	}
	if node.BookID != hint.BookID {
		return CatalogueOwnerChangedErr
	}
	if bookErr != nil {
		return BookNotFoundErr
	}

	err = check(node, c.DisplayStatus)
	if err != nil {
		return err
	}
	if node.DisplayStatus == c.DisplayStatus {
		return tx.Commit().Error
	}

	result := tx.Model(&Catalogue{}).Where("id = ? AND book_id = ?", node.ID, node.BookID).
		UpdateColumn("display_status", c.DisplayStatus)
	if result.Error != nil {
		return result.Error
	}
	if result.RowsAffected != 1 {
		return fmt.Errorf("catalogue %d display update affected %d rows", node.ID, result.RowsAffected)
	}
	if node.DisplayStatus == enum.DisplayVisible && c.DisplayStatus == enum.DisplayHidden {
		err = node.hideDescendants(tx)
		if err != nil {
			return err
		}
	}
	return tx.Commit().Error
}

// hideDescendants 使用调用方的事务逐批隐藏同书后代. 接收者是已锁定的目标行.
func (c *Catalogue) hideDescendants(tx *gorm.DB) error {
	const batchSize = 256
	pending := []int64{c.ID}
	seen := map[int64]struct{}{c.ID: {}}
	lock := clause.Locking{Strength: "UPDATE"}

	for len(pending) > 0 {
		count := min(len(pending), batchSize)
		parentIDs := pending[:count]
		pending = pending[count:]

		// 查出所有直接子节点, 已隐藏的中间目录也可能有可见后代.
		var childIDs []int64
		err := tx.Model(&Catalogue{}).Clauses(lock).
			Where("book_id = ? AND parent_id IN ?", c.BookID, parentIDs).
			Order("id ASC").Pluck("id", &childIDs).Error
		if err != nil {
			return err
		}
		if len(childIDs) == 0 {
			continue
		}
		for _, id := range childIDs {
			if _, exists := seen[id]; exists {
				return fmt.Errorf("%w: book %d, node %d", CatalogueCycleErr, c.BookID, id)
			}
			seen[id] = struct{}{}
		}

		// 本批子节点可能都已隐藏, 更新零行也成功.
		err = tx.Model(&Catalogue{}).
			Where("book_id = ? AND parent_id IN ?", c.BookID, parentIDs).
			Where("display_status <> ?", enum.DisplayHidden).
			UpdateColumn("display_status", enum.DisplayHidden).Error
		if err != nil {
			return err
		}
		pending = append(pending, childIDs...)
	}
	return nil
}

现有控制器controller/v1/catalogue/catalogue.go 
// Display 校验请求, 应用节点显隐规则并返回统一响应.
func Display(c *gin.Context) {
	req := &reqCatalogue.DisplayReq{}
	body := &resp_body.RespBody{}
	err := bindCatalogueRequest(c, req)
	if err != nil {
		body.ValidateError(err)
		c.JSON(http.StatusOK, body)
		return
	}

	catalogue := &biz.Catalogue{}
	err = catalogue.Display(c.Request.Context(), req)
	if err != nil {
		var dbErr *sys_error.DatabaseError
		switch {
		case errors.Is(err, sys_error.CatalogueNotFoundErr):
			body.CatalogueNotFoundError()
		case errors.Is(err, sys_error.BookNotFoundErr):
			body.BookNotFoundError()
		case errors.Is(err, sys_error.CatalogueSortRequiredErr):
			body.CatalogueSortRequiredError()
		case errors.As(err, &dbErr):
			body.DBError(dbErr)
		default:
			body.InternalError(err)
		}
		c.JSON(http.StatusOK, body)
		return
	}

	body.Success(map[string]any{})
	c.JSON(http.StatusOK, body)
}

联调与并发验收

在隔离数据中准备两本书。第一本有可见的第一章、同级第二章；第一章下放置可见正文、隐藏的插图目录及其中的可见图片说明，再加一个 sort=NULL 的隐藏附录。先用 /v1/catalogue/tree 记录两本书的状态和序号，再用 Postman 的 Bearer Token 和 raw → JSON 发送首节请求。

操作用目录树或数据库复核
将可见的第一章设为隐藏，再读取两本书。返回 200。第一章、正文、插图目录、图片说明和待排附录全部隐藏，包括原先位于隐藏目录下的可见孙节点。祖先、第二章、另一本书的全部节点和两本书自身的显隐均保持原值，所有序号保持原值。
接上例，重新显示第一章。返回 200，只有第一章显示。已排序的正文和 sort=NULL 的附录都保留隐藏；再次请求显示仍为 200。
再次将可见的第一章隐藏，单独显示已排的正文，随后对已隐藏的第一章重复提交隐藏。均返回 200。最后一次请求跳过遍历和更新，第一章仍隐藏，正文仍显示。
把可见根节点隐藏，再单独显示根；另选一个已排叶节点，依次切换显示和隐藏。隐藏根时同书根下的全部节点隐藏；再显示根时仅根显示，根的序号仍为 0。叶节点切换仅影响自己。
对待排文件或文件夹先请求显示，再请求隐藏。依次得到 20303 和 200。最终仍是 NULL / hidden。
已有同层排序快照。甲先手动隐藏已排节点，乙再用该快照将它移到另一个已排位置。两次都成功。节点采用新序号并保留手动隐藏，仅改显隐不会让排序快照失效。
甲先通过排序将节点移回待排区，乙再请求显示；随后交换两个操作的提交顺序做对照。排序先提交时，显示请求看到 NULL，返回 20303。显示先提交时，两次都可成功，最终由排序写为 NULL / hidden。
两个管理员为同一个已排节点提交不同的合法目标。两个请求均可成功，最终值等于最后提交的目标。可在一个事务持有书籍锁时发起另一个请求，确认它在锁释放后使用最新行。
并发执行“隐藏可见的第一章”和“显示已排的正文”。以取得同一本书写锁的顺序为准。隐藏先提交，随后单独显示的正文可见；显示先提交，随后级联的结果为整章隐藏。
准备超过 256 个子文件夹，每个都有可见叶节点；再单独测试在较深一层更新时让数据库报错。正常提交时所有分支都变为隐藏。数据库更新失败返回 10201，选中节点和先前成功处理的各层恢复到请求前的状态。
在隔离数据中让可见节点的父子链接成环，从环上的节点请求隐藏。遍历再次遇到已访问 ID 时返回 500，整笔回滚，所有节点保留原值。
在隔离测试中，让节点的 book_id 在预查之后、取得书籍锁之前发生变化。请求只定位一次，锁后复核失败即回滚，响应体 code=500。目标节点保留原显示状态。
按已删除的节点 ID 提交；传数值 ID、未知状态、缺少 catalogue、连续两个 JSON 对象；使用无效或过期令牌。节点缺失返回 20301；参数问题返回 10101；令牌返回 20004 或 20003。错误响应的 data 都是空对象。
