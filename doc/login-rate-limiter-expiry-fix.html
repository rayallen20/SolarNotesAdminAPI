LOGIN RATE LIMIT / FOLLOW-UP

登录限流
过期客户端回收方案

针对容量已满后，过期客户端仍占用位置的问题，给现有单进程限流器增加按需清理。

5 次 / 60 秒最多 1,000 个客户端仅文档 · 手动实施

容量满时先判断是否可能存在过期记录。 到期后及时清理；尚未到期时直接拒绝新客户端，避免每次拒绝都扫描整个映射。

代码块可单独展开和复制。
01 / PROBLEM

为什么容量已满后仍会误拒绝

原实现最多每隔一个 loginWindow 扫描一次全部客户端。如果某个客户端恰好在扫描结束后过期，它仍会占用位置，直到下一次扫描。映射达到上限时，新客户端会因此被拒绝。

时间示例过程
12:00:00执行一次清理，更新 lastCleanup。
12:00:101,000 个客户端的最近一次放行请求都已记录，容量达到上限。
12:01:00请求触发定期清理；这些客户端的最后一次请求仍在窗口内，因此保留。
12:01:10 之后这些记录已过期。原实现可能仍拒绝新客户端，直到下一次定期清理；本方案会在有新客户端请求时及时回收。

记录是否过期按该客户端最后一次被放行的请求时间判断。仍在窗口内的客户端不能为了腾位置而删除，否则其限流次数会被重置。

02 / DESIGN

定期清理 + 满额时按需清理

保留当前的滑动窗口规则，并新增 nextExpiry：记录最早可能出现过期客户端的时间。只有映射满额且新客户端到来时，才使用它判断是否需要提前扫描。

01 · 新客户端检查当前客户端数量。
→
02 · 容量已满尚未到 nextExpiry：直接拒绝。
→
03 · 可能到期清理过期记录后，再判断容量。
TIME

到期时间

每个客户端的最后一次放行时间加上 loginWindow。

SAFETY

只回收过期项

保留窗口内的记录及其限流次数。

EFFICIENCY

减少无效扫描

已知没有记录到期时，满额请求不逐次扫描映射。

定期清理仍会在请求到达时检查和执行；本方案没有启动后台 goroutine。进程空闲时不会主动清理内存，但下次请求到达会重新判断。

03 / IMPLEMENTATION

替换限流器实现

以下完整文件基于当前工程的 middleware/login_rate_limiter.go：保持 loginMaxRequest = 5、loginWindow = time.Minute、loginMaxClients = 1000 和现有响应方法。请在手动合并时保留你自己后续新增的内容。

nextExpiry 的零值即可表示尚未记录到期时间；现有构造函数不需要额外初始化它。路由、中间件响应、配置文件及数据库均不需要为此方案变更。

替换完整文件middleware/login_rate_limiter.go
package middleware

import (
	"SolarNotesAdminAPI/resp_body"
	"sync"
	"time"

	"github.com/gin-gonic/gin"
)

const (
	loginWindow     = time.Minute // loginWindow 本常量用于定义记录请求登录接口次数的时间窗口
	loginMaxRequest = 5           // loginMaxRequest 本常量用于定义在 loginWindow 时间窗口内允许的最大请求次数
	loginMaxClients = 1000        // loginMaxClients 本常量用于定义在 loginWindow 时间窗口内同时跟踪的客户端数量
)

// LoginRateLimiter 本结构体用于在单个进程内按客户端 IP 地址限制请求登录接口的次数,以防止暴力破解攻击
type LoginRateLimiter struct {
	mu          sync.Mutex             // mu 保护 requests、lastCleanup 和 nextExpiry 的并发访问
	requests    map[string][]time.Time // requests 本字段用于为每个客户端保存当前窗口内已放行请求的时间戳列表,用于计算请求次数
	lastCleanup time.Time              // lastCleanup 本字段用于记录上一次移除过期客户端记录的时间
	nextExpiry  time.Time              // nextExpiry 最早可能出现过期记录的时间，可能早于实际到期时间
}

// NewLoginRateLimiter 本函数用于创建一个新的 LoginRateLimiter 实例,并初始化其 requests 字段
func NewLoginRateLimiter() *LoginRateLimiter {
	return &LoginRateLimiter{
		requests: make(map[string][]time.Time),
	}
}

// Handle 本方法用于在请求登录接口时检查客户端 IP 地址的请求频率
// 若超过限制则返回访问频率限制响应体
// 否则继续处理请求
func (l *LoginRateLimiter) Handle(c *gin.Context) {
	// 控制浏览器/代理服务器,不要缓存本次响应的内容
	c.Header("Cache-Control", "no-store")

	if !l.allow(c.ClientIP()) {
		respBody := &resp_body.RespBody{}
		respBody.LoginRateLimitError()
		c.AbortWithStatusJSON(200, respBody)
		return
	}

	c.Next()
}

// allow 判断客户端是否可以发起登录请求；成功时记录本次请求。
func (l *LoginRateLimiter) allow(clientIP string) bool {
	l.mu.Lock()
	defer l.mu.Unlock()

	now := time.Now()
	cutoff := now.Add(-loginWindow)

	// 定期清理，避免未满容量时长期保留过期客户端。
	if l.lastCleanup.IsZero() || now.Sub(l.lastCleanup) >= loginWindow {
		l.cleanupExpired(now)
	}

	history, exists := l.requests[clientIP]
	first := 0
	for first < len(history) && !history[first].After(cutoff) {
		first++
	}
	history = history[first:]

	if len(history) >= loginMaxRequest {
		return false
	}

	// 容量已满且有记录可能到期时，先回收过期客户端。
	if !exists && len(l.requests) >= loginMaxClients {
		if l.nextExpiry.IsZero() || !now.Before(l.nextExpiry) {
			l.cleanupExpired(now)
		}
		if len(l.requests) >= loginMaxClients {
			return false
		}
	}

	l.requests[clientIP] = append(history, now)
	newExpiry := now.Add(loginWindow)
	if l.nextExpiry.IsZero() || newExpiry.Before(l.nextExpiry) {
		l.nextExpiry = newExpiry
	}
	return true
}

// cleanupExpired 清除窗口内没有请求的客户端，并更新下次可能过期的时间。
// 调用前必须持有 l.mu；此方法不再加锁，避免重复加锁。
func (l *LoginRateLimiter) cleanupExpired(now time.Time) {
	cutoff := now.Add(-loginWindow)
	var nextExpiry time.Time

	for ip, history := range l.requests {
		if len(history) == 0 {
			delete(l.requests, ip)
			continue
		}

		lastRequestTime := history[len(history)-1]
		if !lastRequestTime.After(cutoff) {
			delete(l.requests, ip)
			continue
		}

		expiresAt := lastRequestTime.Add(loginWindow)
		if nextExpiry.IsZero() || expiresAt.Before(nextExpiry) {
			nextExpiry = expiresAt
		}
	}

	l.nextExpiry = nextExpiry
	l.lastCleanup = now
}
04 / EXPLANATION

实现中的关键判断

1. 为什么取最后一次请求时间？

history 按放行时间顺序追加。只有最后一次放行请求也已离开窗口，整个客户端条目才可以删除。因此先判空，再读取 lastRequestTime；当其小于或等于 cutoff 时删除。

2. 为什么 nextExpiry 可以早于实际到期时间？

假设某客户端原本将在 12:01:00 到期，随后又在 12:00:30 发起了一次被放行的请求，它的实际到期时间变为 12:01:30。nextExpiry 可能暂时仍是 12:01:00；若此时容量已满并收到新客户端，请求会触发一次扫描，随后按现有记录重新计算。提前扫描是安全的，不会删除未过期记录。

3. 为什么清理方法不再加锁？

allow() 已持有 mu，并在锁内调用 cleanupExpired()。该方法依赖调用方持锁，不能在其他位置无锁调用，也不能在内部再次给同一个互斥锁加锁。

容量达到上限且所有客户端仍在窗口内时，新客户端仍会被拒绝。这是容量限制的既定行为。单进程内存限流的计数在进程重启后清空；多实例各自计数，需使用共享存储或网关策略。

package middleware

import (
	"fmt"
	"sync"
	"sync/atomic"
	"testing"
	"time"
)

// TestRateLimiterReclaimsExpiredAtCapacity 验证容量已满时会及时回收过期客户端。
func TestRateLimiterReclaimsExpiredAtCapacity(t *testing.T) {
	limiter := NewLoginRateLimiter()
	now := time.Now()
	limiter.lastCleanup = now.Add(-time.Second)
	limiter.nextExpiry = now.Add(-500 * time.Millisecond)
	for i := 0; i < loginMaxClients; i++ {
		limiter.requests[fmt.Sprint(i)] = []time.Time{now.Add(-loginWindow - 500*time.Millisecond)}
	}

	if !limiter.allow("new-client") {
		t.Fatal("已过期的记录应被清理，新客户端应获得位置")
	}
	if len(limiter.requests) != 1 {
		t.Fatalf("清理后应只保留新客户端，实际数量：%d", len(limiter.requests))
	}
}

// TestRateLimiterPreservesActiveClients 验证满额时不删除有效记录，也不反复扫描。
func TestRateLimiterPreservesActiveClients(t *testing.T) {
	limiter := NewLoginRateLimiter()
	now := time.Now()
	limiter.lastCleanup = now.Add(-time.Second)
	limiter.nextExpiry = now.Add(loginWindow - 2*time.Second)
	for i := 0; i < loginMaxClients; i++ {
		limiter.requests[fmt.Sprint(i)] = []time.Time{now.Add(-2 * time.Second)}
	}
	previousCleanup := limiter.lastCleanup

	for i := 0; i < 100; i++ {
		if limiter.allow("new-client") {
			t.Fatal("所有位置均有效时应拒绝新客户端")
		}
	}
	if !limiter.lastCleanup.Equal(previousCleanup) {
		t.Fatal("记录未到期时不应反复进行清理")
	}
	if len(limiter.requests) != loginMaxClients {
		t.Fatal("不应删除仍在窗口内的客户端记录")
	}
}

// TestRateLimiterRecalculatesStaleExpiry 验证过早的 nextExpiry 会被重新计算。
func TestRateLimiterRecalculatesStaleExpiry(t *testing.T) {
	limiter := NewLoginRateLimiter()
	now := time.Now()
	limiter.lastCleanup = now.Add(-time.Second)
	limiter.nextExpiry = now.Add(-time.Millisecond)
	for i := 0; i < loginMaxClients; i++ {
		limiter.requests[fmt.Sprint(i)] = []time.Time{now}
	}

	if limiter.allow("new-client") {
		t.Fatal("有效记录已满时应拒绝新客户端")
	}
	if !limiter.nextExpiry.After(now) {
		t.Fatal("应根据有效记录重新计算 nextExpiry")
	}
	previousCleanup := limiter.lastCleanup
	if limiter.allow("another-client") {
		t.Fatal("有效记录已满时应拒绝其他新客户端")
	}
	if !limiter.lastCleanup.Equal(previousCleanup) {
		t.Fatal("重新计算后不应在到期前重复清理")
	}
}

// TestRateLimiterKeepsLiveQuota 验证只删除过期记录，并保留有效客户端的限流次数。
func TestRateLimiterKeepsLiveQuota(t *testing.T) {
	limiter := NewLoginRateLimiter()
	now := time.Now()
	limiter.lastCleanup = now.Add(-time.Second)
	limiter.nextExpiry = now.Add(-500 * time.Millisecond)
	limiter.requests["expired"] = []time.Time{now.Add(-loginWindow - 500*time.Millisecond)}
	for i := 0; i < loginMaxClients-1; i++ {
		limiter.requests[fmt.Sprint(i)] = []time.Time{now, now, now, now, now}
	}

	if !limiter.allow("new-client") {
		t.Fatal("新客户端应使用已过期记录释放的位置")
	}
	if len(limiter.requests) != loginMaxClients {
		t.Fatal("清理并加入新客户端后，记录数量应等于上限")
	}
	if limiter.allow("1") {
		t.Fatal("有效客户端原有的限流次数不应被清除")
	}
}

// runLoginAttempt 执行一次并发请求，并统计被放行的次数。
func runLoginAttempt(limiter *LoginRateLimiter, accepted *atomic.Int64, wg *sync.WaitGroup) {
	defer wg.Done()
	if limiter.allow("same-client") {
		accepted.Add(1)
	}
}

// TestRateLimiterConcurrentRequests 验证并发请求不会突破单客户端额度。
func TestRateLimiterConcurrentRequests(t *testing.T) {
	limiter := NewLoginRateLimiter()
	var accepted atomic.Int64
	var wg sync.WaitGroup

	for i := 0; i < 100; i++ {
		wg.Add(1)
		go runLoginAttempt(limiter, &accepted, &wg)
	}
	wg.Wait()

	if got := accepted.Load(); got != int64(loginMaxRequest) {
		t.Fatalf("允许的请求数应为 %d，实际为 %d", loginMaxRequest, got)
	}
}
