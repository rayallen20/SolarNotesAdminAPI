POST /v1/book/update

编辑一本书的标题与显隐

管理员打开某本书的编辑抽屉，修改标题或显示状态，再点击保存。服务端按书籍 ID 锁定这本书，核对打开抽屉时的两个原值，再保存目标值。书序由调序接口管理，书内各级目录沿用各自的显隐状态。

书籍编辑抽屉原型 · 前后端编辑契约 · 创建书籍的字段约定

请求与响应

沿用管理员 Bearer 鉴权，POST 请求使用 application/json。book.id 是正 int64 的十进制字符串，同名书以 ID 区分。前端分别保存打开抽屉时的原值 expected 和表单草稿 target。只改其中一项时，另一项也要随两个对象完整提交。取消编辑直接关闭抽屉。

data.book 使用现有 book/options 的单本摘要结构。页面按字符串 ID 替换对应行并更新显隐统计。如果返回的 sort 与本地列表不同，重新加载该天体的完整书单，以同步其他行的顺序。书籍摘要 DTO

快照与目标使用不同的书名校验

字段绑定规则作用
book、expected、target必填对象，缺失或 null 返回 10101。缺少快照或目标时无法完成核对。
expected.title必填 JSON 字符串，保留原文。用 *string 区分显式空串和缺失。允许提交实际读到的历史值，例如带首尾空白、超过 20 个码点或空串的标题，以便管理员修正它。
target.title复用请求包已有的 Title。按 jstext.TrimSpace 修整首尾后接受 1 至 20 个 Unicode 码点。保存规范化后的书名，允许与另一本书同名。
两个 display_status均必填且精确取 visible 或 hidden。原值参与冲突判断，目标值只控制书籍自身。

例如数据库存着 " Go "，抽屉应将含空格的原文发在 expected.title 中。提交目标 " Go " 时，后端将它修整为 "Go" 并保存。两个字段若都绑定到现有的 Title，即使没人编辑也会误判冲突。已有的 Title 实现

锁定单本书，核对快照后写入

在 model/book.go 为现有 model.Book 增加 Update。接收者携带主键和目标值，两个参数携带原始标题和显隐。通过主键 SELECT ... FOR UPDATE 读取最新记录并持锁到事务结束，所有读写使用同一 tx。

取得书籍行锁后的情况处理结果
查无此书返回已有的 BookNotFoundErr，映射为 20202。
当前标题或显隐与 expected 不符返回 20204，整次操作回滚。即使当前值恰好等于 target，也要先报告原快照失效。
快照匹配，目标与当前值相同跳过 SQL 更新，提交事务并返回锁定时读取的书籍摘要。
快照匹配，标题或显隐有变化显式写 title 与 display_status 两列并检查影响一行，提交成功后回填模型。

标题在 Go 中逐字节比较，大小写、首尾空格及 Unicode 组合形式都会保留差异。这样冲突判断独立于 MySQL 列的排序规则。调序只改变 sort，它不参与快照比较。若调序已先提交，编辑将读到新的 sort 并随摘要返回。整个编辑事务只需锁这本书，既无需锁天体，也无需查询或更新 catalogue。

查看模型方法与事务代码

事务中将最新数据读入局部变量 current。只有 Commit() 成功后才写回接收者，因此查询、更新及提交错误均可沿错误链返回。该实现使用现有列和主键，无需调整数据库结构。

业务层接收完整请求，提交后回填摘要

biz.Book.Update(ctx, req) error 接收完整请求，把原值和目标值交给模型。成功后回填 ID、Title、Sort 和 DisplayStatus。本次查询只读取书籍行，直接映射这四个字段即可。现有 fillByORM 还会访问 record.Planet，适用于已加载天体的创建及分页列表场景。现有业务实体与回填方法

控制器组装摘要，并注册鉴权路由

在现有 controller/v1/book/book.go 中增加 Update。控制器用 ShouldBindJSON 绑定请求，调用业务方法，再用 respBook.OptionResp 构造 data.book。这些片段沿用各现有文件的导入。路由放在受全局鉴权中间件保护的 v1 路由组中。

查看控制器方法
业务码前端处理
10101请求字段无效。保留表单，让管理员修正。
20202书籍已被删除。结束该条编辑，刷新当前天体书单。

10201、500数据库或内部错误。若连接中断或提交结果未知，重新读取书单核对结果再决定是否重提。

已处理的业务结果沿用 HTTP 200，失败时 data 始终为空对象。20203 留给后续书序冲突。下面是两名管理员编辑同一本书时，后提交的一方可能收到的响应。

联调验收

先调用 POST /v1/book/options 取得测试天体的书单，保存目标行的字符串 ID、原标题、显隐和序号。每个成功用例均核对响应的四个字段，并再次读取书单确认持久化结果。

操作预期
选择两本同名书中的一本，分别尝试只改标题、只改显隐和同时修改仅匹配 ID 的书被编辑。显隐可双向切换，书序与所属天体保持原值，目录树中各节点原有状态保留。
目标标题修整后为 20 或 21 个码点，或只有空白。再试缺失对象、非法枚举、裸数字 ID20 个码点可保存，其余无效输入均为 10101。快照中缺失或为 null 的标题也为 10101。
库中原标题带首尾空白或超过 20 个码点，目标标题合法提交准确原文可以修正旧值。若原快照误删空白或只改了大小写，返回 20204。
两个管理员基于同一快照，一个改名，另一个改显隐先提交的改动生效。另一方取得锁后发现原值不符，返回 20204。两个字段按整份快照校验，已提交的改动得到保留。
使用最新快照原样保存，再用已失效的快照请求相同的目标值前者 200 并返回摘要，后者 20204。可用两个独立请求复核先核对、后判断是否需要更新的顺序。
打开抽屉后只有书序变动，再保存标题返回 200 及更新后的序号，书序得到保留。在测试库可用已提交的书序变动模拟后续调序接口。
目标书被删除，或请求使用缺失、过期的令牌有效请求引用已删除的书返回 20202。鉴权失败由中间件提前处理。
