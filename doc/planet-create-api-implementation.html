先修正当前 Create() 的判断

当前 biz.Planet.Create() 已接收完整的 *planet.CreateReq 并检查空指针，但尚未完成插入。存在性分支的处理方向相反：

FindByName 结果当前实现本方案
err == nil直接返回 nil，看起来创建成功，但没有写入。名称已存在，返回 sys_error.PlanetExistErr。
PlanetNotFoundErr返回“请求创建的天体已存在”。允许继续生成 ID 并插入。

02 / IMPLEMENTATION

请求与响应约定

POST/v1/planet/create

请求头使用 Content-Type: application/json 和 Authorization: Bearer <完整 JWT>。该 API 已在 main.newRouter() 注册，并受全局鉴权中间件保护。

请求对象的外层键为 planet。前端现有演示方法接收的是三个字段的普通对象，接入 HTTP 时需要包入这一层；本文不修改前端。

JSON 示例创建 Earth 的请求体 
{

    "title": "我们的蓝色星球",
    "intro": "地球是太阳系中目前已知存在生命的行星。"

03 / IMPLEMENTATION

数据库约束与创建流程

2026-11-16 通过只读 SHOW CREATE TABLE solar_notes.planet 核验了本地表结构：

列 / 约束当前定义实现方式
idBIGINT NOT NULL，主键，无自增。调用 snowflake.Next()；GORM 显式标记 autoIncrement:false。
nameVARCHAR(20) NOT NULL；唯一索引 uk_name(name)。请求绑定限制九个规范名称；唯一索引保证同名最多一条。
title / introVARCHAR(50) / VARCHAR(255)，utf8mb4。请求层采用更严格的 20 / 150 码点上限。
created_at / updated_at默认 CURRENT_TIMESTAMP；updated_at 自动更新时间。本次 INSERT 不提供这两个列，由数据库填充。
存储引擎 / 表名InnoDB / planet。沿用 SingularTable 配置，不新增 TableName()。

本地表已具备需要的约束，无需新增列、重复创建唯一索引或执行 AutoMigrate。其他部署环境应核对同一约束是否存在。name 当前排序规则为 utf8mb4_0900_ai_ci；API 的 oneof 校验仍要求精确、区分大小写的规范名称。

  1. 01 / AUTH & BIND鉴权与参数校验

    全局中间件确认管理员，控制器绑定嵌套请求对象。

  2. 02 / LOOKUP检查名称

    查到即拒绝；未找到才继续；数据库故障立即返回。

  3. 03 / ID生成雪花 ID

    使用已经在 initApp 中初始化的发号器。

  4. 04 / INSERT插入一条记录

    使用 Create 执行 INSERT；不执行 Save 或覆盖更新。

  5. 05 / UNIQUE处理并发冲突

    索引阻止重复插入；冲突后确认名称是否已存在。

  6. 06 / RESPONSE组装成功响应

    写入成功后填充业务实体，由控制器实例化 DTO。

先查再插并不能保证并发安全。 两个请求可能同时查不到 Earth；最终只能由 uk_name 让其中一个 INSERT 成功。单行写入可沿用 GORM 的默认事务，无须为“查询不存在”另外开启多语句事务。MySQL 对违反唯一约束的普通 INSERT 返回错误，并回滚该语句。MySQL 官方说明 ↗

04 / IMPLEMENTATION

请求参数沿用现有 binding 规则

下面是当前文件，作为接口契约保留，无须重复添加字段。嵌套 Planet 指针必须非 nil，内部字段由 ShouldBindJSON() 校验；notblank 已在启动时注册。

沿用当前文件param/req/v1/planet/create.go 
package planet

// CreateReq 本结构体用于定义请求创建天体接口时的请求体
type CreateReq struct {
	Planet *CreatePlanetReq `json:"planet" binding:"required"`
}

// CreatePlanetReq 本结构体用于定义请求创建天体接口时的天体信息
type CreatePlanetReq struct {
	Name  string `json:"name" binding:"required,oneof=Sun Mercury Venus Earth Mars Jupiter Saturn Uranus Neptune"` // Name 天体标识(必须精确匹配预定义名称)
	Title string `json:"title" binding:"required,notblank,max=20"`                                                 // Title 简介标题
	Intro string `json:"intro" binding:"required,notblank,max=150"`                                                // Intro 简介内容
}

required 排除空字符串；notblank 排除全为空白的文本；oneof 排除未知或大小写不符的名称。业务方法保留接收者、context、请求和嵌套对象的判空，不再重复这些字段规则。

本方案按当前请求约束接受数据并原样入库。前端已经在提交前对标题与简介 trim；如果 Postman 提交合法但带首尾空格的文本，后端会保留这些空格，长度也按原始文本校验。未在此 API 中新增自动裁剪或规范化行为。

长度口径沿用当前实现。 validator 的 max 按 Unicode 码点计数，前端 .length / maxlength 按 UTF-16 代码单元计数，例如 😀 在两端分别计为 1 与 2。本文没有把两者声明为完全相同，也没有引入尚未注册的 utf16max；需要严格统一时，应另行调整校验契约。validator v10.30.1 源码 ↗

如果将来还有 HTTP 之外的调用入口，调用方应先完成同等请求校验再调用 biz.Planet.Create()。

06 / IMPLEMENTATION

模型增加插入和唯一键冲突分类

以下为 model/planet.go 完整内容，保留状态接口依赖的 FindByNames()。新增 Insert() 是模型成员方法；业务层无需导入 MySQL 驱动。FindByName() 使用局部结果对象，因此不会把接收者中已有的 ID 隐式带入名称查询。

替换完整文件model/planet.go 
package model

import (
	"SolarNotesAdminAPI/db"
	"context"
	"errors"

	"github.com/go-sql-driver/mysql"
	"gorm.io/gorm"
)

// PlanetNotFoundErr 本错误用于将数据库记录不存在转换为业务层可识别的错误
var PlanetNotFoundErr = errors.New("planet not found")

// PlanetDuplicateKeyErr 表示插入触发唯一键冲突,可能来自名称或主键,不能直接解释为名称已存在
var PlanetDuplicateKeyErr = errors.New("planet duplicate key")

// Planet 本结构体用于和数据库中的planet表进行映射
type Planet struct {
	ID    int64  `gorm:"column:id;primaryKey;autoIncrement:false"` // ID 行星的唯一标识符,由雪花发号器生成
	Name  string `gorm:"column:name"`                              // Name 行星名称 (用于前台前端匹配3D资源)
	Title string `gorm:"column:title"`                             // Title 行星标题
	Intro string `gorm:"column:intro"`                             // Intro 行星简介
}

// FindByNames 本方法用于根据给定的行星名称列表查询行星信息
func (p *Planet) FindByNames(ctx context.Context, names []string) ([]*Planet, error) {
	var planets []*Planet
	err := db.DB.WithContext(ctx).Where("name IN ?", names).Find(&planets).Error
	if err != nil {
		return nil, err
	}

	return planets, nil
}

// FindByName 本方法用于根据给定的行星名称查询行星信息
func (p *Planet) FindByName(ctx context.Context, name string) (*Planet, error) {
	if p == nil {
		return nil, errors.New("nil planet model")
	}
	if ctx == nil {
		return nil, errors.New("nil planet query context")
	}
	if db.DB == nil {
		return nil, errors.New("database is not initialized")
	}

	var planet Planet
	err := db.DB.WithContext(ctx).Where("name = ?", name).First(&planet).Error
	if errors.Is(err, gorm.ErrRecordNotFound) {
		return nil, PlanetNotFoundErr
	}

	if err != nil {
		return nil, err
	}

	return &planet, nil
}

// Insert 本方法用于插入接收者表示的一条天体记录,不覆盖已有记录
// 唯一键冲突通过错误链保留类别和底层原因,供业务层进一步判断
func (p *Planet) Insert(ctx context.Context) error {
	if p == nil {
		return errors.New("nil planet model")
	}
	if ctx == nil {
		return errors.New("nil planet insert context")
	}
	if db.DB == nil {
		return errors.New("database is not initialized")
	}
	if p.ID <= 0 {
		return errors.New("planet ID must be positive")
	}

	result := db.DB.WithContext(ctx).Create(p)
	err := result.Error
	if err != nil {
		// 兼容启用 GORM 错误翻译的情况;当前工程尚未开启该配置
		if errors.Is(err, gorm.ErrDuplicatedKey) {
			return errors.Join(PlanetDuplicateKeyErr, err)
		}

		// 当前 MySQL 驱动直接返回 MySQLError;1062 表示唯一键冲突
		var mysqlErr *mysql.MySQLError
		if errors.As(err, &mysqlErr) && mysqlErr.Number == 1062 {
			return errors.Join(PlanetDuplicateKeyErr, err)
		}

		return err
	}

	if result.RowsAffected != 1 {
		return errors.New("planet insert did not affect exactly one row")
	}

	return nil
}

当前 db.Connect() 未启用 TranslateError，所以实现通过 errors.As() 读取 *mysql.MySQLError 的编号 1062。兼容分支同时识别启用错误翻译后的 gorm.ErrDuplicatedKey，无需改变全局数据库配置。驱动已经在 go.mod 中，未新增业务依赖。GORM 错误处理文档 ↗

errors.Join(PlanetDuplicateKeyErr, err) 同时保留“唯一键冲突”分类和底层错误：业务层用 errors.Is 识别类别，诊断时仍可用 errors.As 找到 MySQL 错误。

1062 不等于“名称重复”。 主键 ID 冲突也会返回 1062，所以模型只返回通用的 PlanetDuplicateKeyErr；下一节业务层通过名称复查决定是否返回 PlanetExistErr。单纯 ID 冲突仍返回数据库错误。

使用 Create(p) 执行普通 INSERT，并确认错误为空、影响行数为 1。不要换成 Save、REPLACE 或冲突时更新，否则“重复创建被拒绝”的约定会改变。GORM 创建记录文档 ↗

完成 biz.Planet.Create()

以下为 biz/planet.go 完整内容。新增 snowflake 导入，修正 Create 方法，并保留 ShowStatus、fillByORM 与 flush。

替换完整文件biz/planet.go 
package biz

import (
	"SolarNotesAdminAPI/model"
	"SolarNotesAdminAPI/param/req/v1/planet"
	"SolarNotesAdminAPI/snowflake"
	"SolarNotesAdminAPI/sys_error"
	"context"
	"errors"
)

// names 行星名称列表,用于前端匹配 3D 资源
var names = [9]string{
	"Sun",
	"Mercury",
	"Venus",
	"Earth",
	"Mars",
	"Jupiter",
	"Saturn",
	"Uranus",
	"Neptune",
}

// Planet 本结构体用于表示星球业务实体
type Planet struct {
	ID    int64  // ID 行星的唯一标识符
	Name  string // Name 行星名称 (用于前台前端匹配3D资源)
	Title string // Title 行星标题
	Intro string // Intro 行星简介
	Exist bool   // Exist 行星是否存在 (用于判定能否创建该天体)
}

// ShowStatus 本方法用于查询所有行星的状态,并返回一个包含行星状态的切片
func (p *Planet) ShowStatus(ctx context.Context) ([]*Planet, error) {
	if p == nil || ctx == nil {
		return nil, &sys_error.InternalError{
			Cause: errors.New("nil planet entity or context"),
		}
	}

	planetNames := make([]string, 0, len(names))
	for _, name := range names {
		planetNames = append(planetNames, name)
	}

	orm := &model.Planet{}
	records, err := orm.FindByNames(ctx, planetNames)
	if err != nil {
		return nil, &sys_error.DatabaseError{Cause: err}
	}

	recordsByName := make(map[string]*model.Planet, len(records))
	for _, record := range records {
		if record == nil {
			return nil, &sys_error.InternalError{
				Cause: errors.New("nil planet record"),
			}
		}

		recordsByName[record.Name] = record
	}

	planets := make([]*Planet, 0, len(recordsByName))
	for _, name := range planetNames {
		planet := &Planet{
			Name:  name,
			Exist: false,
		}

		record, exists := recordsByName[name]
		if exists {
			planet.fillByORM(ctx, record)
			planet.Exist = true
		}

		planets = append(planets, planet)
	}

	return planets, nil
}

// fillByORM 本方法用于将数据库查询结果填充到业务实体中
func (p *Planet) fillByORM(ctx context.Context, record *model.Planet) {
	p.ID = record.ID
	p.Name = record.Name
	p.Title = record.Title
	p.Intro = record.Intro
}

// Create 本方法用于根据已通过参数校验的请求创建天体
// 仅在插入成功后填充业务实体;请求字段的必填、枚举和长度由控制器绑定时校验
func (p *Planet) Create(ctx context.Context, req *planet.CreateReq) error {
	if p == nil {
		return &sys_error.InternalError{
			Cause: errors.New("nil planet entity"),
		}
	}

	// 在其余检查之前清空旧状态,避免实例复用时失败仍残留上一次的创建结果
	p.flush(ctx)

	if ctx == nil {
		return &sys_error.InternalError{
			Cause: errors.New("nil context"),
		}
	}

	if req == nil {
		return &sys_error.InternalError{
			Cause: errors.New("nil create request"),
		}
	}

	if req.Planet == nil {
		return &sys_error.InternalError{
			Cause: errors.New("nil create planet request"),
		}
	}

	orm := &model.Planet{}
	_, err := orm.FindByName(ctx, req.Planet.Name)
	if err != nil {
		if !errors.Is(err, model.PlanetNotFoundErr) {
			return &sys_error.DatabaseError{Cause: err}
		}
	} else {
		return sys_error.PlanetExistErr
	}

	// 发号器已经在 main.initApp 中初始化;不接受客户端指定 ID
	orm = &model.Planet{
		ID:    snowflake.Next(),
		Name:  req.Planet.Name,
		Title: req.Planet.Title,
		Intro: req.Planet.Intro,
	}
	err = orm.Insert(ctx)
	if err != nil {
		if errors.Is(err, model.PlanetDuplicateKeyErr) {
			// 两个请求可能同时通过前置查询,由 name 唯一索引阻止重复插入
			// 1062 也可能是 ID 冲突,因此按名称再次确认,不把全部冲突都当作重名
			_, findErr := orm.FindByName(ctx, req.Planet.Name)
			if findErr == nil {
				return sys_error.PlanetExistErr
			}
			if !errors.Is(findErr, model.PlanetNotFoundErr) {
				return &sys_error.DatabaseError{Cause: errors.Join(err, findErr)}
			}
		}

		return &sys_error.DatabaseError{Cause: err}
	}

	p.fillByORM(ctx, orm)
	p.Exist = true

	return nil
}

// flush 本方法用于清空天体业务实体的所有字段,以防止实例复用导致的旧数据残留
func (p *Planet) flush(ctx context.Context) {
	p.ID = 0
	p.Name = ""
	p.Title = ""
	p.Intro = ""
	p.Exist = false
}

清理实体放在接收者判空之后，即使后续 context 或请求为 nil，也不会留下上一次创建的 ID、内容或 Exist。当前 flush 不使用 context，因此允许在 context 校验之前调用。

前置查询只减少已存在名称的无效 INSERT。并发竞争仍由唯一索引处理：遇到 PlanetDuplicateKeyErr 时再次按名称查询，名称存在则返回 PlanetExistErr；名称不存在则保留原插入错误；复查发生数据库故障则将两个原因一起包装。

只有 INSERT 完成后才调用 fillByORM 并设置 Exist=true。Exist 是现有业务实体的状态字段，不是数据库列，也不需要作为创建响应的一部分。

雪花发号器已在 main.initApp() 初始化。创建失败可能消耗一个 ID，这是正常的；不需要回收 ID 或要求编号连续。多个服务实例应使用不同的 node_id。

package planet

import (

// ShowStatus 本函数用于显示天体的可用状态信息
func ShowStatus(c *gin.Context) {
	respBody := &resp_body.RespBody{}
	planetBiz := &biz.Planet{}
	planets, err := planetBiz.ShowStatus(c.Request.Context())
	if err != nil {
		var dbErr *sys_error.DatabaseError
		if errors.As(err, &dbErr) {
			respBody.DBError(dbErr)
			c.JSON(http.StatusOK, respBody)
			return
		}

		respBody.InternalError(err)
		c.JSON(http.StatusOK, respBody)
		return
	}

	resp := &respPlanet.ShowStatusResp{
		Planets: make([]*respPlanet.ShowStatusPlanetResp, 0, len(planets)),
	}

	for _, planet := range planets {
		planetResp := &respPlanet.ShowStatusPlanetResp{
			Name:  planet.Name,
			Exist: planet.Exist,
		}

		resp.Planets = append(resp.Planets, planetResp)
	}

	data := map[string]interface{}{
		"planets": resp.Planets,
	}
	respBody.Success(data)

	c.JSON(http.StatusOK, respBody)
}

// Create 本函数用于创建天体
func Create(c *gin.Context) {
	req := &planet.CreateReq{}
	respBody := &resp_body.RespBody{}

	err := c.ShouldBindJSON(req)
	if err != nil {
		respBody.ValidateError(err)
		c.JSON(http.StatusOK, respBody)
		return
	}

	planetBiz := &biz.Planet{}
	err = planetBiz.Create(c.Request.Context(), req)
	if err != nil {
		var dbErr *sys_error.DatabaseError
		switch {
		case errors.Is(err, sys_error.PlanetExistErr):
			respBody.PlanetExistError()
		case errors.As(err, &dbErr):
			respBody.DBError(err)
		default:
			respBody.InternalError(err)
		}

		c.JSON(http.StatusOK, respBody)
		return
	}

	// 业务层只负责创建和填充实体,由控制器组装响应 DTO
	createResp := &respPlanet.CreateResp{
		Planet: &respPlanet.CreatePlanetResp{
			ID:    strconv.FormatInt(planetBiz.ID, 10),
			Name:  planetBiz.Name,
			Title: planetBiz.Title,
			Intro: planetBiz.Intro,
		},
	}
	respBody.Success(map[string]any{
		"planet": createResp.Planet,
	})

	c.JSON(http.StatusOK, respBody)
}

成功时 ID 用 strconv.FormatInt 转为字符串，且只把 DTO 放入 map[string]any{"planet": createResp.Planet}，符合你的统一包装器约定。

  1. 先调用登录 API，在 Authorization → Bearer Token 中粘贴 data.admin.access_token 的完整 JWT。
  2. 创建 POST 请求 {{base_url}}/v1/planet/create，在 Body → raw → JSON 填写第 02 节请求体；base_url 使用当前服务地址和配置端口，不包含 /v1。
  3. 选择尚未创建的规范名称。成功时 HTTP 200、业务码 200，data.planet.id 为字符串；随后 GET /v1/planet/status，应看到该名称的 exist=true。
  4. 再次提交同名请求，期望业务码 20101。修改后的标题不能覆盖已经写入的标题。
  5. 依次测试缺少 planet、planet:null、未知名称、小写 earth、空白标题、21 个普通汉字的标题、151 个普通汉字的简介，期望 10101。
  6. 去掉 Authorization，期望 20004；同时提交多个同名创建请求，应只有一条记录成功写入。

Postman 的创建成功请求会实际新增数据。示例 Earth 已存在时，请使用其他尚未创建的名称；本次文档编写没有向本机 MySQL 插入或删除数据。
