HTTP API / REQUEST BODY LIMIT

全局请求体大小
配置实现方案

把请求体上限写入配置，并在每个 API 处理器读取数据前统一检查；登录限流和跨域预检继续按既有约定工作。

所有 API 路由单位：字节含文件上传仅文档 · 手动实施

上限属于整个后端，不是登录接口专用。 配置以字节为单位；超限后沿用 HTTP 200、业务码 10101 和对象形式的 data。

每个代码块可单独展开和复制。
01 / SCOPE

限制范围和返回格式

本方案对使用当前 Gin 引擎的 API 请求体统一执行上限，包括 JSON、表单、二进制、文件上传以及请求长度未知的情况。限制的是服务收到的请求体字节数，不包含请求头；multipart 请求的边界和表单字段也计入。

CONFIG

按环境配置

service.max_request_body_bytes 使用正整数，单位为字节。

EXAMPLE

1 MiB 示例

1048576 字节仅作参考，实际值应结合 API 和上传需求设置。

RESPONSE

沿用现有协议

超限返回 HTTP 200、业务码 10101 和空对象 data。

响应示例 · HTTP 200请求体超限
{
  "code": 10101,
  "message": "请求体超过大小限制",
  "data": {}
}

这个上限也限制上传请求。 方案会在进入业务处理器前把请求体读取到内存：并发请求越多或配置越大，内存消耗越高，并且还存在切片扩容和业务处理开销。若需要大文件上传或流式处理，应先重新设计上传与限额策略，而不是简单地无限调大该值。

02 / CONFIG

在服务配置中声明上限

给现有 conf.Service 增加 MaxRequestBodyBytes，并在已有的 Service.validate() 中要求该值大于 0。Config.validate() 已调用该方法，因此不需要修改配置加载链。

替换完整文件conf/service.go
package conf

import (
	"errors"
	"time"
)

// Service 服务相关配置
type Service struct {
	Port                     string   `yaml:"port"`                        // Port 监听端口
	TrustedProxies           []string `yaml:"trusted_proxies"`             // TrustedProxies 可信代理 IP 或 CIDR 列表,空列表表示不信任代理
	ReadHeaderTimeoutSeconds int64    `yaml:"read_header_timeout_seconds"` // ReadHeaderTimeoutSeconds 读取请求头的最长时间.单位:秒
	ReadTimeoutSeconds       int64    `yaml:"read_timeout_seconds"`        // ReadTimeoutSeconds 读取整个请求的最长时间.单位:秒
	IdleTimeoutSeconds       int64    `yaml:"idle_timeout_seconds"`        // IdleTimeoutSeconds 等待下一个请求的最长空闲时间.单位:秒
	MaxRequestBodyBytes      int64    `yaml:"max_request_body_bytes"`      // MaxRequestBodyBytes API 请求体大小上限，单位字节。
}

// maxServiceTimeoutSeconds 本常量用于表示转换为 time.Duration 时,不会溢出的最大秒数
const maxServiceTimeoutSeconds int64 = (1<<63 - 1) / int64(time.Second)

// validate 本方法校验 HTTP 服务超时及请求体大小配置
func (s *Service) validate() error {
	if s.ReadHeaderTimeoutSeconds <= 0 || s.ReadHeaderTimeoutSeconds > maxServiceTimeoutSeconds {
		return errors.New("service.read_header_timeout_seconds 必须是有效的正秒数")
	}
	if s.ReadTimeoutSeconds <= 0 || s.ReadTimeoutSeconds > maxServiceTimeoutSeconds {
		return errors.New("service.read_timeout_seconds 必须是有效的正秒数")
	}
	if s.IdleTimeoutSeconds <= 0 || s.IdleTimeoutSeconds > maxServiceTimeoutSeconds {
		return errors.New("service.idle_timeout_seconds 必须是有效的正秒数")
	}
	if s.MaxRequestBodyBytes <= 0 {
		return errors.New("service.max_request_body_bytes 必须大于 0")
	}
	if s.ReadTimeoutSeconds < s.ReadHeaderTimeoutSeconds {
		return errors.New("service.read_timeout_seconds 不得小于 read_header_timeout_seconds")
	}
	return nil
}

// ReadHeaderTimeout 本方法用于返回读取请求头的最长时间
func (s *Service) ReadHeaderTimeout() time.Duration {
	return time.Duration(s.ReadHeaderTimeoutSeconds) * time.Second
}

// ReadTimeout 本方法用于返回读取整个请求的最长时间
func (s *Service) ReadTimeout() time.Duration {
	return time.Duration(s.ReadTimeoutSeconds) * time.Second
}

// IdleTimeout 本方法用于返回等待下一个请求的最长空闲时间
func (s *Service) IdleTimeout() time.Duration {
	return time.Duration(s.IdleTimeoutSeconds) * time.Second
}

将以下配置项合并到 config.example.yaml、config.dev.yaml 和准备使用的 config.prod.yaml 的已有 service 段。三个环境可以设置不同的数值。

下方只是片段：保留已有的端口、可信代理和 HTTP 超时字段，不要用它覆盖整个配置文件，也不要创建第二个同名 service 段。加载器启用了严格字段检查，应先增加结构体字段，再填写 YAML。

合并到已有 service 段config.example.yaml / config.dev.yaml / config.prod.yaml
service:
  # 保留已有的 port、trusted_proxies 和三个超时配置项

  # 所有 API 请求体的大小上限，单位：字节；示例值为 1 MiB
  max_request_body_bytes: 1048576

本方案没有隐式默认值：未填写、留空、零值或负数会导致配置加载失败。上限应按机器内存、并发规模和业务请求大小选择；该值不是字符数，也不是可上传文件本身的精确大小。

03 / ORDER

保留跨域预检和登录限流

请求先设置跨域响应头；命中登录路由时，原有 IP 限流先记录请求；接着统一检查请求体；最后应答正常的 OPTIONS 预检或进入 API 处理器。

01 · 跨域响应头让超限等错误也带有现有跨域头。
→
02 · 登录限流只对 POST 登录路由计数。
→
03 · 全局上限校验请求体，然后处理预检或业务。

将现有 CORS 中间件拆成两个处理器

原 Cors() 会提前结束 OPTIONS 请求。把“写跨域头”和“应答预检”分开后，预检请求也能经过请求体上限检查，超限响应仍然具有跨域响应头。这里保留当前开发环境的来源放行策略。

替换完整文件middleware/cors.go
package middleware

import (
	"net/http"

	"github.com/gin-gonic/gin"
)

// CorsHeaders 在处理请求前写入跨域响应头。
func CorsHeaders(c *gin.Context) {
	origin := c.GetHeader("Origin")
	if origin != "" {
		// 开发期不拒绝任何源，生产环境发版之前再收紧。
		c.Header("Access-Control-Allow-Origin", origin)
		c.Header("Vary", "Origin")
		c.Header("Access-Control-Allow-Methods", "GET, POST, PUT, DELETE, OPTIONS")
		c.Header("Access-Control-Allow-Headers", c.GetHeader("Access-Control-Request-Headers"))
		c.Header("Access-Control-Max-Age", "600")
	}
	c.Next()
}

// CorsPreflight 在请求体大小校验通过后应答 OPTIONS 预检请求。
func CorsPreflight(c *gin.Context) {
	if c.Request.Method == http.MethodOptions {
		c.AbortWithStatus(http.StatusNoContent)
		return
	}
	c.Next()
}

仅对登录路由执行原有限流

由于请求体限制需要注册为全局中间件，而登录限流必须先运行，新增一个只匹配登录路由的包装器。它继续使用现有 LoginRateLimiter；其他 API 和 OPTIONS 不使用登录额度。

新增完整文件middleware/login_route_limit.go
package middleware

import (
	"net/http"

	"github.com/gin-gonic/gin"
)

// LoginRouteLimit 仅对指定登录路由执行已有的 IP 限流。
type LoginRouteLimit struct {
	fullPath string            // fullPath 是登录路由的完整路径。
	limiter  *LoginRateLimiter // limiter 是登录路由使用的限流器。
}

// NewLoginRouteLimit 为指定完整路由创建登录限流包装器。
func NewLoginRouteLimit(fullPath string) *LoginRouteLimit {
	return &LoginRouteLimit{
		fullPath: fullPath,
		limiter:  NewLoginRateLimiter(),
	}
}

// Handle 仅对匹配的 POST 登录请求调用原有的限流中间件。
func (l *LoginRouteLimit) Handle(c *gin.Context) {
	if c.Request.Method == http.MethodPost && c.FullPath() == l.fullPath {
		l.limiter.Handle(c)
		return
	}
	c.Next()
}

完整登录路径由 main.go 中的前缀与路径共同生成，路由注册和限流匹配使用同一组值，避免分别硬编码。c.FullPath() 使用 Gin 匹配到的路由路径；未匹配路由返回空字符串。

登录请求即使因请求体超限被拒绝，也会先计入现有登录限流。达到原有限流阈值后，后续登录请求优先返回业务码 20005，不会继续读取请求体。

04 / BODY LIMIT

实现统一请求体检查

请求声明的长度已超过上限时直接拒绝；长度未知或声明值在范围内时，使用 http.MaxBytesReader 限制读取，再将通过检查的原始字节交回后续处理器。读取失败时返回统一文案，不暴露底层错误。

新增完整文件middleware/request_body_limit.go
package middleware

import (
	"bytes"
	"errors"
	"io"
	"net/http"

	"SolarNotesAdminAPI/resp_body"
	"github.com/gin-gonic/gin"
)

// RequestBodyLimit 对进入后端 API 的请求体执行统一的字节数限制。
type RequestBodyLimit struct {
	maxBytes int64 // maxBytes 是每个请求体允许的最大字节数。
}

// NewRequestBodyLimit 创建请求体限制器；上限必须为正数。
func NewRequestBodyLimit(maxBytes int64) (*RequestBodyLimit, error) {
	if maxBytes <= 0 {
		return nil, errors.New("请求体大小上限必须大于 0")
	}
	return &RequestBodyLimit{maxBytes: maxBytes}, nil
}

// Handle 在进入后续处理前读取受限请求体，并恢复供后续处理的请求体。
func (l *RequestBodyLimit) Handle(c *gin.Context) {
	// 已知长度超过上限时，不必读取请求体。
	if c.Request.ContentLength > l.maxBytes {
		l.reject(c, "请求体超过大小限制")
		return
	}

	limitedBody := http.MaxBytesReader(c.Writer, c.Request.Body, l.maxBytes)
	defer limitedBody.Close()

	body, err := io.ReadAll(limitedBody)
	if err != nil {
		var sizeErr *http.MaxBytesError
		if errors.As(err, &sizeErr) {
			l.reject(c, "请求体超过大小限制")
		} else {
			l.reject(c, "读取请求体失败")
		}
		return
	}

	// bytes.NewReader 复用读取结果；下游仍可正常读取原始字节。
	c.Request.Body = io.NopCloser(bytes.NewReader(body))
	c.Next()
}

// reject 以项目既有的参数错误格式终止请求。
func (l *RequestBodyLimit) reject(c *gin.Context, message string) {
	body := &resp_body.RespBody{}
	body.ValidateError(errors.New(message))
	c.Header("Cache-Control", "no-store")
	c.AbortWithStatusJSON(http.StatusOK, body)
}

在当前链路中，前置的跨域处理器和登录限流器不读取请求体。以后新增会读取请求体的中间件时，也应把它放在大小限制之后，否则数据可能在检查前已被读取。

现有登录 Controller 可以继续使用 ShouldBindJSON()。全局中间件已读取并检查完整请求体，再恢复给 Controller；现有的 MaxBytesError 分支可以保留作为备用处理。

05 / REGISTRATION

注册全局中间件

以下完整 main.go 基于当前工程，保留已配置的 HTTP 读取超时、可信代理及开发监听地址。不要再为登录路由额外注册原来的 loginLimiter.Handle，否则会重复计数。

替换完整文件main.go
package main

import (
	"SolarNotesAdminAPI/conf"
	"SolarNotesAdminAPI/controller/v1/admin"
	"SolarNotesAdminAPI/db"
	"SolarNotesAdminAPI/middleware"
	"SolarNotesAdminAPI/snowflake"
	"SolarNotesAdminAPI/validation"
	"errors"
	"log"
	"net/http"

	"github.com/gin-gonic/gin"
)

// main 加载配置与依赖，注册中间件和路由，并启动 HTTP 服务。
func main() {
	err := conf.Load()
	if err != nil {
		log.Fatal(err)
	}
	configInstance := conf.Get()

	err = validation.Register()
	if err != nil {
		log.Fatal(err)
	}

	err = db.Connect(configInstance.Database)
	if err != nil {
		log.Fatal(err)
	}

	err = snowflake.InitSnowflake(configInstance.Snowflake.NodeID)
	if err != nil {
		log.Fatal(err)
	}

	router := gin.Default()
	// Tips: 配置可信任代理 IP 或 CIDR 列表,以便在使用 X-Forwarded-For 等头部时正确获取客户端真实 IP 地址
	// 否则获取到的客户端 IP 地址为前置代理的地址,从而导致登录接口访问频率限制失效
	err = router.SetTrustedProxies(configInstance.Service.TrustedProxies)
	if err != nil {
		log.Fatal(err)
	}
	// 为登录路由提供唯一的路径来源，避免限流匹配和注册路径不一致。
	v1Prefix := "/v1"
	loginPath := "/admin/login"
	loginLimiter := middleware.NewLoginRouteLimit(v1Prefix + loginPath)

	bodyLimit, err := middleware.NewRequestBodyLimit(configInstance.Service.MaxRequestBodyBytes)
	if err != nil {
		log.Fatal(err)
	}

	// 先设置跨域头和登录限流，再限制所有请求体，最后处理预检。
	router.Use(middleware.CorsHeaders, loginLimiter.Handle, bodyLimit.Handle, middleware.CorsPreflight)

	v1 := router.Group(v1Prefix)
	{
		v1.POST(loginPath, admin.Login)
	}

	server := &http.Server{
		// 开发环境沿用当前监听地址。
		Addr: "0.0.0.0:" + configInstance.Service.Port,
		// TODO: 使用同机 Nginx 部署时,将上一行改为:
		// Addr: "127.0.0.1:" + configInstance.Service.Port,
		Handler:           router,
		ReadHeaderTimeout: configInstance.Service.ReadHeaderTimeout(), // 读取完整请求头的最长时间
		ReadTimeout:       configInstance.Service.ReadTimeout(),       // 读取整个请求(包括请求头和请求体)的最长时间
		IdleTimeout:       configInstance.Service.IdleTimeout(),       // 已完成请求的连接,在等待下一个请求时的最长空闲时间
	}

	err = server.ListenAndServe()
	if err != nil && !errors.Is(err, http.ErrServerClosed) {
		log.Fatal(err)
	}
}

原来的 middleware.Cors() 已由 CorsHeaders 和 CorsPreflight 代替。如果其他自定义代码或测试仍调用原方法，也需要按相同顺序更新。请求体上限器使用现有标准库和 Gin，不新增依赖。

// TestRequestBodyLimitConfig 验证请求体上限必须为正数，且不影响现有超时校验。
func TestRequestBodyLimitConfig(t *testing.T) {
	values := []int64{-1, 0, 1, 1048576}
	for _, value := range values {
		service := &Service{
			ReadHeaderTimeoutSeconds: 5,
			ReadTimeoutSeconds:       15,
			IdleTimeoutSeconds:       60,

// testBodyLimitRequest 发送测试请求，unknown 为 true 时模拟未知请求体长度。
func testBodyLimitRequest(router *gin.Engine, method, path, value string, unknown bool) *httptest.ResponseRecorder {
	var reader io.Reader = strings.NewReader(value)
	if unknown {
		reader = io.NopCloser(strings.NewReader(value))
	}
	req := httptest.NewRequest(method, path, reader)
	req.RemoteAddr = "198.51.100.10:4321"
	req.Header.Set("Origin", "https://frontend.example")
	out := httptest.NewRecorder()
	router.ServeHTTP(out, req)
	return out
}

// testErrorCode 读取项目统一响应中的业务码。
func testErrorCode(t *testing.T, out *httptest.ResponseRecorder) int {
	t.Helper()
	var body resp_body.RespBody
	if err := json.Unmarshal(out.Body.Bytes(), &body); err != nil {
		t.Fatal(err)
	}
	if out.Code != http.StatusOK || body.Data == nil {
		t.Fatal("响应状态或 data 对象不符合约定")
	}
	return body.Code
}

// TestGlobalBodyLimitBoundaries 验证全局上限、边界及请求体转发。

		t.Fatal("正常预检应返回 204")
	}
	out = testBodyLimitRequest(router, http.MethodOptions, "/v1/echo", strings.Repeat("x", 17), true)
	if testErrorCode(t, out) != resp_body.ValidateErrorCode {
		t.Fatal("超出上限的预检请求应被拒绝")
	}
	if out.Header().Get("Access-Control-Allow-Origin") != "https://frontend.example" {
		t.Fatal("超大预检响应缺少跨域头")
	}
}

// TestGlobalBodyLimitMultipart 验证上传请求也受上限限制且内容保持完整。

// TestGlobalBodyLimitConcurrent 验证并发请求独立处理各自的请求体。

	}
}

07 / BOUNDARIES

实施前需要了解的边界

  • 大小限制和 ReadTimeout 分别控制字节数量与读取时间，二者可以同时使用；请求读取超时或连接中断时，客户端不一定收到 JSON。
  • 该方案对经过当前 Gin 中间件链的 API 请求生效。Gin 自带的部分路由自动重定向可能在中间件之前返回，不会进入 API 处理器；若要求这类 HTTP 请求也在到达 Gin 前受限，应在前置代理或网关层另配请求体上限。前置代理的超限响应格式可能与业务码不同。
  • 全局中间件会先缓冲请求体，不适合依赖逐块处理的大文件或流式接口。上传请求会受到同一字节上限约束。
  • 示例配置值 1 MiB 不是固定推荐值。调整时同时评估并发请求的内存占用，并确保代理与后端的限制、超时和前端错误处理协调一致。

参考：Go 标准库 MaxBytesReader、Gin v1.12 FullPath。
