POST /v1/book/create

创建书籍时自动追加书序

管理员选定天体，填写标题和初始显隐后提交。后端在创建事务内统计该天体的全部书籍，给新书分配末位。一个天体有 3 本显示、2 本隐藏的书时，下一本的序号是 6。

添加书籍原型 · 书籍管理接口总览 · 当前模型实现

请求与响应

沿用管理员 Bearer 鉴权，请求头设置 Content-Type: application/json。添加表单可以用 books.length + 1 预览序号。Axios 创建请求只提交 planet.id、title 和 display_status。成功后重新读取 POST /v1/book/options，以该天体最新书单上的序号为准。

book 和 book.planet 均为必填对象。天体 ID 是正 int64 的十进制字符串。标题沿用 Title.UnmarshalJSON 和 jstext.TrimSpace，修整后为 1 至 20 个 Unicode 码点，允许同名。display_status 必填，取 visible 或 hidden，原型默认选中显示。一次成功请求只创建一条 book 记录。

本次前后端联调以此处的三字段契约为准。创建请求 DTO 中移除 CreateBookReq.Sort。book.sort 仍是数据库中的书序，业务实体和书单响应都使用它。页面上看到的预览值可能因其他管理员同时添加书籍而改变。

后端改动位置

现有位置改造后的职责
param/req/v1/book/create.go删除 CreateBookReq.Sort 及其绑定标签。控制器继续用 ShouldBindJSON 校验请求。
biz/book.go(*Book).Create(ctx, req) error 保留接收者、上下文、请求及嵌套对象的判空，删除 req.Book.Sort == nil。构造模型时填入雪花 ID、天体 ID、标题与显隐，调用 record.Insert(ctx)。成功后用 fillByORM(ctx, record) 回填实际序号与所属天体。
model/book.go沿用 (*Book).Insert(ctx context.Context) error 及具名事务回调 (*Book).insertWithPlanet(tx *gorm.DB) error。在回调内锁定天体、计算序号并写入模型副本，成功提交后将副本赋回接收者。
controller/v1/book/book.go删除创建流程中“排序值已被占用”的错误映射，按下文区分字段校验、天体不存在、书序异常和数据库错误。成功仍调用 respBody.Success(map[string]any{})。

事务内分配末位

同一天体的创建与后续的 book/reorder 遵循同一加锁顺序，先按主键排他锁定 planet 行，再操作书籍。空书单也有可锁定的天体行。现有 insertWithPlanet 使用的 SHARE 需要改为 GORM 的 clause.Locking{Strength: "UPDATE"}。

  1. 在请求上下文中开始读写事务。建议对此事务使用 sql.LevelReadCommitted。先按 planet_id 对应的主键锁天体，同时读取回填需要的 id, name, title, intro。查无记录则回滚并返回 20102。
  2. 取得天体锁后，用同一 tx 对该天体的 book 做一次聚合，统计所有显示和隐藏书籍。在上述隔离级别下，这条查询可以看到前一个持锁事务刚提交的书。聚合无需给空书单所在的索引范围额外加锁。
  3. 用 uint64 接收数量 N。非空书单必须满足 min_sort == 1 && max_sort == N。在联合唯一约束和非空无符号整数列下，这就证明序号连续。异常时回滚。N >= 4294967295 表示没有下一个合法序号，也要在加一和转换为 uint32 之前返回错误。
  4. 回调的接收者 b 指向模型副本。在回调内设置 b.Sort = uint32(N + 1)，执行 tx.Create(b)，检查 RowsAffected == 1，并将已加载的天体赋给 b.Planet。
  5. 沿用现有具名回调，在 Transaction 的第二个参数传入 &sql.TxOptions{Isolation: sql.LevelReadCommitted}。回调返回错误时事务回滚，事务成功提交后再执行 *b = record 并返回业务层。

并发示例。同一天体已有 5 本书。A 取得锁并插入第 6 本，B 等待。A 提交后，B 在锁内读到 6 本书。B 因此写入第 7 本，即使两个表单打开时都预览为第 6 本。若 A 回滚，B 可以使用第 6 位。不同天体使用各自的天体行。

历史书序与发布

先核对 book.sort 为 INT UNSIGNED NOT NULL，且 (planet_id, sort) 有联合唯一索引。符合上述结构时，改造仅涉及书序数据，无需变更列类型或重建索引。以下查询供上线前在目标库执行。

例如原书序是 [1, 3]，按数量算出的下一位 3 已被占用。先将旧书整理为 [1, 2]，新书才应得到 3。历史序号 0 也参与整理。空天体不会出现在查询结果中，创建第一本时自然得到 1。

按原阅读顺序整理，保留联合唯一索引

  1. 发布窗口先暂停所有会增删书籍或改书序的写入，等待旧事务结束，再做最终检查。保留受影响书籍的 planet_id, id, sort 映射以便核对。每个受影响的天体单独开事务，先锁天体行，再按 sort ASC, id ASC 读取并锁定该天体的书籍行。
  2. 按照读出的固定顺序，给每行计算目标序号 1..N。用宽整数计算，若 N > 4294967295 则停止处理该天体。对需要增大序号的行按旧序号降序更新，再对需要减小序号的行按旧序号升序更新，原值等于目标的行跳过。这样每次先腾出下一行需要的位置，也适用于含有最大无符号整数的旧数据。
  3. 逐行执行下方参数化更新并检查恰好更新一行。比如 [0, 1, 4] 依次执行 1 → 2、0 → 1、4 → 3。事务内复核每个 ID 对应的目标及连续性，通过后提交。任一步失败则回滚该天体的事务。

历史书序检查返回零行后，发布按事务分配末位的后端，并将重构页面的 Axios 创建请求接入上文契约，再开放书籍创建。

错误与前端处理

控制器沿用 HTTP 200 和 {code, message, data} 包装，失败时 data 为空对象。绑定错误由 ShouldBindJSON 处理，事务中的预期错误由业务层映射。

条件业务码与动作
请求字段无效10101，沿用 ValidateError，前端保留表单供修正。
所选天体已不存在20102，沿用 BookPlanetNotFoundError()。页面刷新天体选项。
书序不连续，或序号空间已满建议模型返回可识别的状态错误，业务层包装为 sys_error.InternalError，对外 500。排查时可从错误链查看天体、数量、最小和最大序号。
SQL 查询、插入或提交失败10201，保留原错误并沿用 sys_error.DatabaseError。新流程中分配后的重复键属于异常，可能来自雪花主键或其他写入路径。移除创建路径中针对 MySQL 1062 的排序占用复查，以及业务层、控制器对 BookSortOccupiedErr 的映射。
令牌过期或无效20003 或 20004，由现有鉴权中间件处理。

创建允许同名，也未定义幂等键。连接中断或提交结果未知时，先读取该天体的书单核实，再由管理员决定是否重提。若创建已收到成功响应、仅刷新失败，页面应提示“已保存，列表刷新失败”，重试读取即可。

联调验收

在测试库选用两个天体，记录请求前的 book/options。成功用例核对 data: {}、新增行、所属天体及实际序号。已知回滚的失败用例核对原书单。

场景预期结果
空天体创建隐藏书，再追加显示书得到 1、2，另一天体独立从 1 开始。同名书可分别创建。业务实例在提交后获得真实 Sort 与 Planet。
已有 5 本书，其中 2 本隐藏。打开添加抽屉并提交新书检查 Axios 请求体中的 book 仅含标题、显隐和天体引用。无其他写入时，创建成功后刷新 book/options，新书的 sort 为 6。
校验标题、显隐及天体标题修整后恰好 20 个码点可通过，21 个或全空白返回 10101。显隐缺失、枚举值无效或 ID 格式非法也返回 10101。有效 ID 引用不存在的天体返回 20102。
两条独立连接同时对同一空书单或已有 5 本书的书单发起创建请求两笔均提交成功时，序号分别为 1、2 或 6、7。若先取得锁的事务回滚，另一笔可使用原末位。
两组历史书序分别为 [0,1,4] 和 [1,3]整理前触发连续性检查，创建回滚。整理后原 ID 相对顺序和显隐保留，下一本分别得到 4、3。用构造的聚合值检查上限。N = 4294967294 可分配最后一位，N = 4294967295 拒绝追加。
将来接入调序后，与追加同时执行按取得天体锁的顺序生效。若追加先提交，调序会发现旧书单少了一本。若调序先提交，创建在新顺序末尾追加。每次成功后的书序均为 1..N。
