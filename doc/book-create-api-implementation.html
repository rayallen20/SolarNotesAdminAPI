天体列表 API 实现文档

创建书籍 API

POST/v1/book/create

管理员选择一个已创建的天体，填写书名、排序值和显示状态。后端为书籍生成雪花 ID，写入成功后返回空对象。

请求与成功响应

在 Postman 中选择 POST，地址填写 {{base_url}}/v1/book/create。在 Authorization 页签选择 Bearer Token，Token 栏填写登录返回的完整 JWT。在 Body 中选择 raw 和 JSON，请求的 Content-Type 为 application/json。

JSON请求体
{
  "book": {
    "title": "书籍标题",
    "sort": 1,
    "display_status": "visible",
    "planet": {
      "id": "2000001"
    }
  }
}

先从 GET /v1/planet/list 返回的 data.planets 中选择实际存在的天体，用它的字符串 ID 替换示例中的 "2000001"。

HTTP 200成功响应
{
  "code": 200,
  "message": "success",
  "data": {}
}

提交事务成功后返回空对象。网络中断而无法确定结果时，重复提交同一天体和排序值可能收到排序占用，不能据此认定第一次请求失败。

从添加表单到数据库

前端 /admin/books 的添加抽屉会请求真实天体列表。页面目前显示固定书籍样例，点击确认后仅执行校验；下表给出接入创建接口时的字段映射。书籍表单 · 天体列表请求

请求字段表单字段与接口要求后端处理
book.title先去除首尾空白，再接受 1 至 20 个 Unicode 码点。保存修整后的书名。列为 VARCHAR(50)，接口采用 20 字的业务上限。允许同名。
book.sortJSON 整数。hidden 允许 0 至 2147483647；visible 允许 1 至 2147483647。表单初始值为 1。保留有符号 INT NOT NULL。请求校验和表级 CHECK 同时按显示状态约束下限。
book.display_status必填，精确匹配 visible 或 hidden，表单初始值为 visible。按原值写入同名 ENUM 列。请求漏传时返回参数错误。
book.planet.id表单将所选 planet.id 暂存为 addForm.planet_id；发送时封装为嵌套对象。JSON 使用带引号的十进制字符串，服务端按正 int64 读取、检查天体存在，并写入 book.planet_id。

已核对本地 solar_notes.book 的 InnoDB 表结构。主键 id 为 BIGINT，由服务端调用 snowflake.Next() 生成。数据库负责填充 created_at 和 updated_at；本接口只需要写入五个业务列。

数据库已建有联合唯一索引 uk_planet_sort (planet_id, sort)。 地球和火星可以各有一本排序值为 1 的书。地球已有一本隐藏书占用 1 时，再添加一本可见书也会冲突。同一天体最多有一本隐藏书使用 0，不同天体可各自使用 0。

给现有 book 表添加排序约束

先检查存量数据。下列查询取新约束的反面；sort 和 display_status 在现有表中均为 NOT NULL。

只读 SQL检查违反新规则的记录
SELECT id, planet_id, display_status, sort
FROM solar_notes.book
WHERE NOT (
       (display_status = 'hidden' AND sort >= 0)
   OR (display_status = 'visible' AND sort > 0)
)
ORDER BY planet_id, sort, id;

若查到记录，先按书籍的实际展示顺序为它们选定同一天体下尚未占用的排序值，再重新检查。批量把负数改成 0 或 1 可能触发原有唯一索引。

预检返回空集后执行一次下面的 DDL。MySQL 8.0.16 起会强制执行这类 CHECK。添加时数据库会再次验证已有记录；若此时仍有违规行，添加操作会失败。MySQL 的 CHECK 约束 · ALTER TABLE 对已有记录的检查

迁移 SQL添加显示状态与排序的联合检查
ALTER TABLE solar_notes.book
ADD CONSTRAINT chk_book_display_sort
CHECK (
       (display_status = 'hidden' AND sort >= 0)
   OR (display_status = 'visible' AND sort > 0)
);

执行后可用下面的语句确认表中同时存在 chk_book_display_sort 和 uk_planet_sort。前者约束每一行的状态与排序组合，后者保证同一天体的排序值唯一。

只读 SQL核对最终表结构
SHOW CREATE TABLE solar_notes.book;

约束同时作用于插入和更新。一本排序为 0 的隐藏书要改为可见时，应在同一条 UPDATE 中将状态改为 visible，并把排序设为该天体下未占用的正整数。

绑定请求并校验字段

在 param/req/v1/book/create.go 定义嵌套对象。sort 用 *int32，这样 required 可以拒绝缺失或 null，同时区分显式传入的 0。gte=0 拒绝两种状态下的负数。整数溢出和字段类型错误在 JSON 解码时失败。id,string 让解码器直接从字符串得到整数，全程保留雪花 ID 精度。

复用前端的空白处理规则

需要对齐前端 String.prototype.trim() 的字段可以共用 jstext.TrimSpace。例如，前端会移除两端的 U+FEFF，而 Go 的 strings.TrimSpace 会保留它。把逐字符判断留在 jstext 包内，调用方只需传入完整字符串。ECMAScript trim 规则 · Go strings 实现

新增文件jstext/trim.go
// Package jstext 提供与 JavaScript 字符串行为一致的文本处理函数.
package jstext

import (
	"strings"
	"unicode"
)

// TrimSpace 按 JavaScript String.prototype.trim 的规则移除字符串两端的空白和换行.
func TrimSpace(s string) string {
	return strings.TrimFunc(s, isTrimSpace)
}

// isTrimSpace 判断字符是否属于 JavaScript trim 使用的空白或换行集合.
func isTrimSpace(r rune) bool {
	switch r {
	case '\t', '\n', '\v', '\f', '\r', '\u2028', '\u2029', '\uFEFF':
		return true
	default:
		return unicode.Is(unicode.Zs, r)
	}
}

书名在 JSON 解码时调用公共函数

Title.UnmarshalJSON() 负责解码书名并调用 jstext.TrimSpace。随后 Gin 执行书名字段的 required,max=20 校验。因此，20 个汉字前后各有一个空格时仍能保存，单个表情也只占一个码点。

新增文件param/req/v1/book/create.go
package book

import (
	"encoding/json"

	"SolarNotesAdminAPI/jstext"
)

// CreateReq 定义创建书籍请求的外层对象.
type CreateReq struct {
	Book *CreateBookReq `json:"book" binding:"required"` // Book 是待创建的书籍.
}

// CreateBookReq 定义表单提交的书籍字段.
type CreateBookReq struct {
	Title         Title            `json:"title" binding:"required,max=20"`                        // Title 在绑定时去除首尾空白.
	Sort          *int32           `json:"sort" binding:"required,gte=0"`                          // Sort 为非负整数, 仅 hidden 允许 0.
	DisplayStatus string           `json:"display_status" binding:"required,oneof=visible hidden"` // DisplayStatus 是显示状态.
	Planet        *CreatePlanetRef `json:"planet" binding:"required"`                              // Planet 仅引用已创建天体的 ID.
}

// CreatePlanetRef 定义书籍所属天体.
type CreatePlanetRef struct {
	ID int64 `json:"id,string" binding:"gt=0"` // ID 从 JSON 字符串解码为正 int64.
}

// Title 是已去除首尾空白的书名, max 校验针对处理后的值.
type Title string

// UnmarshalJSON 在 Gin 执行 binding 校验前, 按页面 trim 规则处理书名.
func (t *Title) UnmarshalJSON(data []byte) error {
	var value string
	if err := json.Unmarshal(data, &value); err != nil {
		return err
	}
	*t = Title(jstext.TrimSpace(value))
	return nil
}

在 Gin 绑定时检查可见书籍的排序值

在已有的 validation.Register() 中为 CreateBookReq 注册结构体级校验，使它可以同时读取 DisplayStatus 和 Sort。排序为 0 且状态为可见时，ShouldBindJSON() 会返回带有 visible_sort_gt_zero 标签的校验错误；控制器沿用现有 ValidateError 分支返回 10101，请求在访问数据库之前结束。启动流程已经调用 validation.Register()。

修改现有文件validation/validation.go
package validation

import (
	"errors"
	"reflect"
	"strings"

	reqBook "SolarNotesAdminAPI/param/req/v1/book"

	"github.com/gin-gonic/gin/binding"
	"github.com/go-playground/validator/v10"
)

// Register 本函数用于注册自定义验证器
func Register() error {
	if binding.Validator == nil {
		return errors.New("gin 参数校验器未启用")
	}

	v, ok := binding.Validator.Engine().(*validator.Validate)
	if !ok || v == nil {
		return errors.New("无法获取 Gin 默认参数校验器")
	}

	if err := v.RegisterValidation("notblank", notBlank); err != nil {
		return err
	}
	v.RegisterStructValidation(validateCreateBookSort, reqBook.CreateBookReq{})
	return nil
}

// notBlank 本函数用于检查给定字符串是否至少包含一个非空白字符,非字符串字段不通过校验
func notBlank(field validator.FieldLevel) bool {
	value := field.Field()
	if value.Kind() != reflect.String {
		return false
	}
	return strings.TrimSpace(value.String()) != ""
}

// validateCreateBookSort 检查可见书籍的排序值. 缺失和负数由 Sort 的字段规则报告.
func validateCreateBookSort(sl validator.StructLevel) {
	book := sl.Current().Interface().(reqBook.CreateBookReq)
	if book.Sort != nil && book.DisplayStatus == "visible" && *book.Sort == 0 {
		sl.ReportError(*book.Sort, "Sort", "Sort", "visible_sort_gt_zero", "")
	}
}

在同一事务内关联天体并写入书籍

库中 book.planet_id 与 planet.id 通过 ID 关联，目前没有数据库外键。在事务里按主键对天体行执行 SELECT ... FOR SHARE，再通过同一事务插入书籍，可使其他事务对这行天体的删除等待本次提交或回滚。未来实现天体删除时，还需要为已有关联书籍定义删除规则。MySQL 锁定读取 · GORM 事务

直接由唯一索引裁决并发写入。项目目前保留 MySQL 驱动的原始错误；遇到 1062 时，在当前事务按 (planet_id, sort) 执行锁定读取。如果这个组合存在，才提示排序占用。如果组合仍空闲，可能是雪花主键碰撞，应沿数据库错误路径返回。事务内所有查询使用 tx。PlanetNotFoundErr 复用现有 model/planet.go 的定义。

完整文件model/book.go
package model

import (
	"SolarNotesAdminAPI/db"
	"context"
	"errors"

	"github.com/go-sql-driver/mysql"
	"gorm.io/gorm"
	"gorm.io/gorm/clause"
)

// BookSortOccupiedErr 本错误表示同一天体下的书籍排序值已被其他记录占用
var BookSortOccupiedErr = errors.New("book sort is occupied")

// Book 本结构体用于映射 book 表,只包含本次创建书籍所需的字段.
type Book struct {
	ID            int64   `gorm:"column:id;primaryKey;autoIncrement:false"` // ID 书籍ID
	PlanetID      int64   `gorm:"column:planet_id"`                         // PlanetID 书籍所属天体的 ID
	Title         string  `gorm:"column:title"`                             // Title 书籍标题
	Sort          int32   `gorm:"column:sort"`                              // Sort 书籍在所属天体下的排序值
	DisplayStatus string  `gorm:"column:display_status"`                    // DisplayStatus 书籍的展示状态
	Planet        *Planet `gorm:"-"`                                        // Planet 保存创建成功时读取的所属天体
}

// Insert 本方法用于在事务中确认关联天体存在,并插入接收者表示的书籍记录
// (事务提交成功才返回 nil,查询/插入/提交错误均向调用方传播)
func (b *Book) Insert(ctx context.Context) error {
	if b == nil {
		return errors.New("nil book model")
	}

	if ctx == nil {
		return errors.New("nil book insert context")
	}

	if db.DB == nil {
		return errors.New("database is not initialized")
	}

	if b.ID <= 0 {
		return errors.New("book ID must be positive")
	}

	if b.PlanetID <= 0 {
		return errors.New("book planet ID must be positive")
	}

	// 先在副本上执行事务, 提交成功后再向调用方公开查询结果.
	record := *b
	if err := db.DB.WithContext(ctx).Transaction(record.insertWithPlanet); err != nil {
		return err
	}
	*b = record
	return nil
}

// insertWithPlanet 本函数用于在 Insert 方法中使用的命名事务回调,全部数据库操作共用同一事务
// (关联天体的共享锁持有至事务结束,防止检查通过后天体在插入期间被删除)
func (b *Book) insertWithPlanet(tx *gorm.DB) error {
	if b == nil {
		return errors.New("nil book model")
	}

	if tx == nil {
		return errors.New("nil book insert transaction")
	}

	planet := &Planet{}

	err := tx.Select("id", "name", "title", "intro").
		Clauses(clause.Locking{
			Strength: "SHARE",
		}).
		Where("id = ?", b.PlanetID).
		Take(planet).Error
	if errors.Is(err, gorm.ErrRecordNotFound) {
		return PlanetNotFoundErr
	}

	if err != nil {
		return err
	}

	result := tx.Create(b)
	err = result.Error
	if err != nil {
		// 1062 也可能来自主键冲突,不能直接解释为排序值已被占用
		var mysqlErr *mysql.MySQLError
		if !errors.As(err, &mysqlErr) || mysqlErr.Number != 1062 {
			return err
		}

		// 在同一事务内执行当前读,确认所属天体与排序值的组合是否已存在
		// 使用新的记录接收结果,避免接收者的 ID 意外参与查询条件
		occupied := &Book{}
		findErr := tx.Select("id").
			Clauses(clause.Locking{
				Strength: "SHARE",
			}).
			Where("planet_id = ? AND sort = ?", b.PlanetID, b.Sort).
			Take(occupied).Error
		if findErr == nil {
			return errors.Join(BookSortOccupiedErr, err)
		}

		if errors.Is(findErr, gorm.ErrRecordNotFound) {
			return err
		}

		// 复查失败时同时保留原始插入错误与查询错误,便于排查.
		return errors.Join(err, findErr)
	}

	if result.RowsAffected != 1 {
		return errors.New("book insert did not affect exactly one row")
	}

	b.Planet = planet
	return nil
}

模型沿用现有单数表名配置，映射到 book 表。天体的加锁查询一次读出 id、name、title 和 intro。model.Book.Planet 保存这份快照，gorm:"-" 告诉 GORM 在读写书籍表时忽略该字段。Insert() 在副本上执行事务，提交成功后才把结果赋给模型接收者，业务层可以直接复用查询结果。当前创建只新增一行书籍，catalogue 根节点的初始化留给目录功能。

业务入口与错误分类

新增两个业务错误，供控制器使用 errors.Is 匹配。模型错误描述数据库层的判断，业务错误携带管理员可以读懂的提示；其他数据库错误保留底层原因，交给项目已有的 DatabaseError。

biz.Book.Create() 直接接收完整的请求对象。路由正常进入时，启动流程已初始化雪花发号器，Gin 已完成字段校验。只有 record.Insert(ctx) 成功后，才调用 b.fillByORM(ctx, record)。该方法统一填充书籍 ID、标题、排序和显示状态，并复用 Planet.fillByORM() 填充所属天体，将 Exist 设为 true。Create() 仍只返回 error；如果创建失败，原有业务实例保留调用前的值。

完整文件biz/book.go
package biz

import (
	"context"
	"errors"

	"SolarNotesAdminAPI/model"
	reqBook "SolarNotesAdminAPI/param/req/v1/book"
	"SolarNotesAdminAPI/snowflake"
	"SolarNotesAdminAPI/sys_error"
)

// Book 承载书籍创建业务.
type Book struct {
	ID            int64   `json:"id"`             // ID 书籍ID
	Title         string  `json:"title"`          // Title 书籍标题
	Sort          int32   `json:"sort"`           // Sort 书籍在所属天体下的排序值
	DisplayStatus string  `json:"display_status"` // DisplayStatus 书籍的展示状态
	Planet        *Planet `json:"planet"`         // Planet 书籍所属天体
}

// Create 本函数用于创建书籍
func (b *Book) Create(ctx context.Context, req *reqBook.CreateReq) error {
	if b == nil {
		return &sys_error.InternalError{Cause: errors.New("nil book entity")}
	}

	if ctx == nil || req == nil || req.Book == nil || req.Book.Planet == nil || req.Book.Sort == nil {
		return &sys_error.InternalError{Cause: errors.New("missing book creation arguments")}
	}

	input := req.Book
	record := &model.Book{
		ID:            snowflake.Next(),
		PlanetID:      input.Planet.ID,
		Title:         string(input.Title),
		Sort:          *input.Sort,
		DisplayStatus: input.DisplayStatus,
	}

	err := record.Insert(ctx)
	if err != nil {
		switch {
		case errors.Is(err, model.PlanetNotFoundErr):
			return sys_error.BookPlanetNotFoundErr
		case errors.Is(err, model.BookSortOccupiedErr):
			return sys_error.BookSortOccupiedErr
		default:
			return &sys_error.DatabaseError{Cause: err}
		}
	}

	b.fillByORM(ctx, record)
	return nil
}

// fillByORM 本函数用于将书籍记录及其已加载的所属天体填入业务实体
func (b *Book) fillByORM(ctx context.Context, record *model.Book) {
	planet := &Planet{Exist: true}
	planet.fillByORM(ctx, record.Planet)

	*b = Book{
		ID:            record.ID,
		Title:         record.Title,
		Sort:          record.Sort,
		DisplayStatus: record.DisplayStatus,
		Planet:        planet,
	}
}

组装响应并注册受保护的路由

下列两个业务码是本方案新增的约定。20102 归入天体错误组，20201 用于书籍排序冲突。书籍响应码和 RespBody 的响应方法都写入现有的 resp_body/resp_body.go。下方三个片段依次给出导入位置、常量位置和方法位置。两个方法都调用已有的 failure()，错误响应的 data 为 {}。

package book

import (
	"errors"
	"net/http"

	"SolarNotesAdminAPI/biz"
	reqBook "SolarNotesAdminAPI/param/req/v1/book"
	"SolarNotesAdminAPI/resp_body"
	"SolarNotesAdminAPI/sys_error"

	"github.com/gin-gonic/gin"

// Create 绑定创建书籍请求, 调用业务层并写入统一响应.
func Create(c *gin.Context) {
	req := &reqBook.CreateReq{}
	respBody := &resp_body.RespBody{}
	if err := c.ShouldBindJSON(req); err != nil {
		respBody.ValidateError(err)
		c.JSON(http.StatusOK, respBody)
		return
	}

	bookBiz := &biz.Book{}
	if err := bookBiz.Create(c.Request.Context(), req); err != nil {
		var dbErr *sys_error.DatabaseError
		switch {
		case errors.Is(err, sys_error.BookPlanetNotFoundErr):
			respBody.BookPlanetNotFoundError()
		case errors.Is(err, sys_error.BookSortOccupiedErr):
			respBody.BookSortOccupiedError()
		case errors.As(err, &dbErr):
			respBody.DBError(dbErr)
		default:
			respBody.InternalError(err)
		}
		c.JSON(http.StatusOK, respBody)
		return
	}

	respBody.Success(map[string]any{})
	c.JSON(http.StatusOK, respBody)
}
