POST /v1/admin/password/change

修改当前管理员密码

管理员提交原密码和新密码。后端在同一笔事务中核对发起请求的会话、验证原密码、更新密码摘要并撤销会话。只有事务提交成功，前端才清空登录态并跳转登录页。

前后端对接定义 · 修改密码表单原型 · 现有登录与鉴权业务

请求与响应

使用现有管理员 Bearer 鉴权，请求头携带 Authorization: Bearer <access_token> 和 Content-Type: application/json。下例是演示值。管理员 ID 从鉴权上下文取得；确认新密码由前端逐字比较，两次输入一致才发请求。

接口对成功和失败都返回 HTTP 200、数值型业务码和空对象 data: {}。收到业务码 200 后，前端清空三个输入框，调用 userStore.clearSession() 和 router.replace({name: 'login'})，提示管理员使用新密码登录。新的 JWT 由下一次成功登录签发。

业务码触发条件页面行为
20006 新增会话仍有效，原密码与数据库不匹配；固定提示“原密码不正确”。保留会话与表单，定位原密码输入框。
10101JSON 绑定或字段校验失败。留在表单，提示检查输入。
20003 / 20004JWT 过期为 20003。缺失、无效、撤销、管理员已不存在，或写入前令牌已被并发登录替换，为 20004。交给公共鉴权处理，回到登录页。
10201 / 500数据库操作失败为 10201；已存非空摘要损坏等内部异常为 500。显示通用失败提示。若请求超时或连接中断，结果未知，提示用新密码登录核实，避免自动重复提交。

校验密码字段，保留输入原值

在 param/req/v1/admin/change_password.go 新建请求 DTO。原密码须为非空白字符串，允许核验不符合现行长度限制的历史密码。新密码须为 6–20 个 Unicode 码点且含非空白字符。沿用登录接口的 notblank 和 Gin 字符串长度校验；前后空格计入长度，参与验证和保存的始终是原始字符串。登录请求 · 现有 notblank 规则

缺少 admin、必填字段缺失、值为 null、类型错误或新密码长度越界均返回 10101。原密码通过校验后，允许新旧密码完全相同，该请求仍会撤销原会话。

把本次已验证的会话带进事务

同一个管理员可以先后持有不同 JWT。中间件验证令牌 A 后，另一处登录可能把库里的令牌替换成 B。控制器必须同时传递管理员 ID 和 本次令牌 A 的摘要，事务取得行锁后才能识别这次会话替换。

共用摘要比较方法

当前管理员模型的 password_hash 和 token_hash 使用 SHA-256 十六进制摘要。保留 auth.SHA256Hex、InvalidHashErr 和登录依赖的 MatchSHA256 签名。将比较步骤提取出来，供已经拿到 32 字节摘要的改密事务直接调用。十六进制解码兼容大小写，摘要内容用恒定时间比较。此处的密码格式是与现有登录数据的兼容约定。现有摘要实现

中间件在鉴权成功后保存摘要

为下面两个中间件文件分别导入 "crypto/sha256"。在 AdminAuth.Handle 里把新增语句放在现有 c.Set(adminIDContextKey, administrator.ID) 之后、c.Next() 之前。保留原来的 ID 设置和 CurrentAdminID(c)。摘要源自本次通过 Authenticate 的 rawToken，控制器无需再次解析请求头或 JWT。

两个上下文值都由服务端设置。请求体只接收两项密码，即使客户端传入其他管理员的 ID 或用户名，也只能操作自己。原始 JWT 只用于现有鉴权过程。

在行锁内核验会话、修改密码并撤销令牌

为 model.Admin 新增方法。使用与工程其他写接口相同的 READ COMMITTED 事务，通过管理员主键执行 SELECT ... FOR UPDATE。锁一直持有到事务结束。新的模型方法只接收三个固定长度的摘要，两个密码的原文均无需传入 DAO。

  1. 先重新读取该行的 token_hash。查无记录、摘要已清空、或已换成另一有效摘要时，结束事务并返回 20004。这一步在核验原密码前执行，另一个已经通过入口鉴权的旧请求也会得到正确的会话失效提示。
  2. 会话匹配后，核验锁定记录的 password_hash。原密码输错返回 20006；库存摘要的十六进制格式损坏时返回 500。两条路径都在写入前结束。
  3. 用一个 Updates(map[string]any{...}) 显式写入新密码摘要和空字符串 token_hash。即使新旧密码相同，有效会话的摘要也会从非空变为空。核对影响一行后提交；执行失败由事务回滚。

在现有 import 块加入 "crypto/sha256"、"database/sql"、"encoding/hex"、"SolarNotesAdminAPI/auth" 和 "gorm.io/gorm/clause"。使用项目现有的 model.Admin 表映射及 AdminNotFoundErr，无需修改数据库结构。管理员模型

与并发登录的关系。保留现有 UpdateTokenHash() 中按管理员 ID 和读取时的 password_hash 条件写令牌的逻辑。若登录先写入令牌 B，携带 A 的改密请求会发现会话已换并返回 20004。若改为不同的新密码先提交，已验证旧密码的在途登录条件更新会落空，沿用登录的 20002。同密码改密也会让 A 失效；仍持正确密码的登录请求可以成功签发一个独立的新 JWT。

由业务层转换错误，统一包装响应

在 biz/admin.go 增加 "crypto/sha256" 导入。控制器用已鉴权 ID 初始化 biz.Admin；ChangePassword() 接收完整请求和令牌摘要，直接对密码的原始 UTF-8 字节求摘要。模型提交成功即可返回，后续控制器只需返回空对象。

在现有 sys_error/admin_error.go 增加原密码错误，在 resp_body/resp_body.go 增加业务码及响应方法。登录失败继续使用 20001；改密中的 20006 单独交给原密码输入框处理。

绑定请求，注册受保护路由

在 controller/v1/admin/admin.go 增加 "SolarNotesAdminAPI/auth" 和 "SolarNotesAdminAPI/middleware" 导入。失败路径继续使用 HTTP 200，错误响应始终保留空对象 data。对于绑定错误使用 ValidateError(nil) 的固定消息；数据库和内部错误使用各自的包装类型，对外只显示通用文案。

在 newRouter() 内的 v1.POST(loginPath, admin.Login) 下方注册。改密经过现有的全局请求体大小限制和管理员鉴权，并沿用鉴权中间件的 Cache-Control: no-store。免鉴权集合仍只配置登录路由。

部署时通过 HTTPS 传输密码与令牌。业务日志、诊断和错误响应都应避开密码、原始 JWT 和摘要值；现有 GORM 日志启用了 ParameterizedQueries，保留该设置。数据库日志配置

并发与联调验收

使用隔离测试管理员，先通过 POST /v1/admin/login 取得令牌 A。在 Postman 选择 Bearer Token，以 GET /v1/planet/list 检查 A 是否仍有效。每组用例以已知密码和有效会话开始。

场景核验结果
成功改为不同的新密码返回 200 和 {}，A 访问受保护接口得到 20004。旧密码登录得到 20001，新密码登录取得 B，B 可访问同一接口。
原密码输错，或遗漏原密码的尾随空格返回 20006，A 仍有效。使用正确原值可以重新提交；原密码不额外限制为 6–20 个码点。
新密码长 5、6、20、21 个码点；使用 emoji、首尾空格、纯空白，以及 null 或非字符串6 和 20 为合法边界，单个非 BMP 字符按一个码点计数。5、21、纯空白及结构错误返回 10101。首尾空格按原值计数，重新登录时也必须保留。
新旧密码相同返回 200；A 再访问得到 20004，同一密码可重新登录取得新令牌。
两标签页持 A，同时提交不同新密码只有一笔成功，另一笔返回 20004。只有胜出的新密码能登录。
A 已通过入口鉴权，在事务锁定前另一处登录换成 B用 A 发起的改密得到 20004，即使它携带的原密码也有误。原密码和 B 保持有效。
无令牌、过期令牌；在请求体夹带其他管理员 ID缺失令牌得到 20004，过期得到 20003。有效请求只会更新鉴权上下文对应的管理员。
模拟数据库写入失败；另测损坏的密码摘要前者返回 10201，回滚后原密码和 A 仍有效；后者返回 500。响应和日志均可按固定文案及错误类别核对。
前端两次新密码输入不一致；提交后网络中断前者在确认字段提示，Network 中无请求。后者提示核实登录结果；只有收到本次业务成功响应才显示改密成功。
