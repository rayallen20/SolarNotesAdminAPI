ADMIN AUTHENTICATION / IMPLEMENTATION

管理员鉴权中间件
实现文档

除登录接口外，API 在执行业务处理器之前，必须通过 JWT 校验和数据库当前令牌摘要比对。

全局默认鉴权Bearer JWT校验 token_hashHTTP 200 + 业务码文档方案 · 手动实施

JWT 证明签名和有效期；数据库摘要确认这枚令牌仍被允许使用。 只有两项检查均通过，才把管理员 ID 写入请求上下文并继续执行。

两处追加方法、两个新增文件、一份 main.go 注册示例。
01 / CONTRACT

哪些请求放行，哪些请求拒绝

唯一免鉴权的业务路由是 POST /v1/admin/login。匹配同时检查 HTTP 方法和 Gin 已匹配的完整路由；名称包含 login、路径前缀相似或使用其他请求方法，都不会因此免鉴权。

其他 API，包括现有 GET /v1/planet/status，统一从 Authorization: Bearer <完整 JWT> 请求头读取令牌。使用 Bearer 头传递令牌的格式可参见 RFC 6750 §2.1 ↗。

OPTIONS 预检沿用现有 CORS 处理。 它会在鉴权之前由 CorsPreflight 返回 204 并终止，不进入业务处理器。真正的 GET、POST 等 API 请求仍需鉴权。

鉴权阶段的情况JSON 业务码处理结果
JWT 有效，管理员存在，token_hash 匹配由业务接口决定写入管理员 ID，继续执行。
未携带令牌、Bearer 格式不正确、重复 Authorization 头20004拒绝，不查询管理员记录。
签名、算法、声明或管理员 ID 不合法20004拒绝，不查询管理员记录。
JWT 仅因过期而失败20003拒绝，不查询管理员记录。
管理员已删除、摘要为空或与当前 JWT 不匹配20004拒绝，令牌已不再有效。
数据库查询失败10201拒绝，不把数据库故障解释为正常登录状态。
配置异常、非空摘要格式损坏等内部错误500拒绝，返回统一内部错误消息。

以上错误沿用项目的 HTTP 200 + JSON 业务码 约定，data 为 {}。鉴权中间件不重定向页面，也不会在成功时提前发送响应。

}

02 / FLOW

HTTP、业务和模型各自承担职责

  1. 01 / MIDDLEWARE读取 Bearer 令牌

    仅登录路由跳过；其他请求必须提供唯一的 Authorization 头。

  2. 02 / AUTH验证 JWT

    复用 ParseAdminToken，验证签名、HS256、iss、aud、exp、iat、jti 和管理员 ID。

  3. 03 / MODEL读取管理员记录

    按已验证的 ID 查询 id、name、token_hash。

  4. 04 / BUSINESS比对当前摘要

    复用 MatchSHA256，对完整 JWT 计算摘要并与数据库值比较。

  5. 05 / CONTEXT保存确认后的身份

    通过 c.Set 保存 int64 类型的管理员 ID。

  6. 06 / CONTROLLER执行原有业务

    鉴权成功后调用 c.Next；失败则 AbortWithStatusJSON 并 return。

现有 auth.ParseAdminToken() 已限定签名算法、要求过期时间并检查预期签发方和受众，本方案直接复用它。对应解析选项可参见 golang-jwt/v5 文档 ↗。

文件实施方式职责
model/admin.go追加 FindByID 方法读取鉴权需要的数据库字段。
biz/admin.go追加 Authenticate 方法执行令牌校验、记录检查和摘要比对。
middleware/admin_auth.go新增完整文件路由放行、请求头解析、调用业务层、返回错误。

实现使用当前的 JWT 配置、token_hash 列、错误类型和响应包装器，不需要新增配置项、数据库列或业务依赖。模型和业务实体的方法仍放在各自已有的文件中。

03 / MODEL

追加按管理员 ID 查询的方法

将下面的完整方法追加到 model/admin.go，与 FindByName()、UpdateTokenHash() 同属 model.Admin。所需的 context、errors、db、gorm 导入已存在。

追加完整方法model/admin.go 
// FindByID 根据已验证 JWT 中的管理员 ID 查询当前身份和令牌摘要。
// 只读取鉴权需要的字段,不加载密码摘要;不存在时返回 AdminNotFoundErr。
func (a *Admin) FindByID(ctx context.Context, id int64) error {
	if a == nil {
		return errors.New("administrator model is nil")
	}
	if ctx == nil {
		return errors.New("administrator query context is nil")
	}
	if id <= 0 {
		return errors.New("administrator ID must be positive")
	}
	if db.DB == nil {
		return errors.New("database is not initialized")
	}

	// 使用临时记录,避免接收者原有 ID 参与 GORM 的查询条件。
	record := &Admin{}
	err := db.DB.WithContext(ctx).
		Select("id", "name", "token_hash").
		Where("id = ?", id).
		Take(record).Error
	if errors.Is(err, gorm.ErrRecordNotFound) {
		return AdminNotFoundErr
	}
	if err != nil {
		return err
	}

	*a = *record
	return nil
}

使用新的局部 record 承接结果，避免复用接收者时把旧 ID 隐式带入查询。鉴权不需要密码摘要，因此只查询 id、name 和 token_hash。

这一节是追加方法，不是替换整个文件。请保留已有 Admin 结构体、AdminNotFoundErr 和登录相关查询、更新方法。

04 / BUSINESS

追加业务层鉴权方法

将下列方法追加到 biz/admin.go。它只处理业务逻辑并返回错误；HTTP 响应交给中间件。当前文件所需导入和 flush() 方法均已存在。

追加完整方法biz/admin.go 
// Authenticate 验证 JWT 及数据库中的当前令牌摘要。
// 成功时只填充 ID 和 Username;失败时返回错误,不生成 HTTP 响应。
func (a *Admin) Authenticate(ctx context.Context, rawToken string) error {
	if a == nil {
		return &sys_error.InternalError{Cause: errors.New("nil administrator entity")}
	}
	a.flush()

	if ctx == nil {
		return &sys_error.InternalError{Cause: errors.New("nil authentication context")}
	}
	if rawToken == "" {
		return auth.InvalidTokenErr
	}

	config := conf.Get()
	if config == nil {
		return &sys_error.InternalError{Cause: errors.New("configuration is not loaded")}
	}
	options := &auth.JWTOptions{
		Issuer:     config.JWT.Issuer,
		Audience:   config.JWT.Audience,
		Lifetime:   config.JWT.Lifetime(),
		SigningKey: config.JWT.SigningKey(),
	}

	// 复用已有解析器,先验证签名、算法、标准声明、有效期和管理员 ID。
	adminID, err := auth.ParseAdminToken(rawToken, options)
	if err != nil {
		if errors.Is(err, auth.ExpiredTokenErr) || errors.Is(err, auth.InvalidTokenErr) {
			return err
		}
		return &sys_error.InternalError{Cause: err}
	}

	// 每次受保护请求都读取当前摘要,以便识别被清空或替换的令牌。
	record := &model.Admin{}
	err = record.FindByID(ctx, adminID)
	if errors.Is(err, model.AdminNotFoundErr) {
		return auth.InvalidTokenErr
	}
	if err != nil {
		return &sys_error.DatabaseError{Cause: err}
	}
	if record.TokenHash == "" {
		return auth.InvalidTokenErr
	}

	// MatchSHA256 对原始 JWT 计算摘要,并进行恒定时间比较。
	matched, err := auth.MatchSHA256(rawToken, record.TokenHash)
	if err != nil {
		// 非空摘要格式损坏属于内部数据错误,不能放行请求。
		return &sys_error.InternalError{Cause: err}
	}
	if !matched {
		return auth.InvalidTokenErr
	}

	a.ID = record.ID
	a.Username = record.Name
	return nil
}

错误类别与身份填充

  • 解析器报告令牌过期或无效时，保留原错误，让中间件使用 errors.Is() 分类。
  • 管理员记录不存在、摘要为空或不匹配，都返回 auth.InvalidTokenErr。
  • 数据库故障包装为 DatabaseError；配置和非空摘要格式错误包装为 InternalError，保留底层 Cause。
  • 方法开始时清空旧业务状态，成功后只填充 ID 和 Username。不会把密码摘要或原始令牌填入本次鉴权的业务实体。

先校验 JWT，再查询数据库。因此一枚已经过期的令牌会先得到 20003；不会再查询其数据库摘要是否也已被清空。若过期同时伴随签名或其他声明错误，则由现有解析器归为无效令牌。

鉴权读取当前数据库状态，每个通过 JWT 检查的受保护请求执行一次管理员查询。本方案不缓存 token_hash，以便后续请求读取到撤销后的值。

05 / MIDDLEWARE

新增鉴权中间件与身份读取函数

鉴权中间件

新增 middleware/admin_auth.go。实例只保存登录路由配置；令牌和管理员业务实体都在每次请求内创建，避免不同请求共享身份状态。

新增完整文件middleware/admin_auth.go 
package middleware

import (
	"SolarNotesAdminAPI/auth"
	"SolarNotesAdminAPI/biz"
	"SolarNotesAdminAPI/resp_body"
	"SolarNotesAdminAPI/sys_error"
	"errors"
	"net/http"
	"strings"

	"github.com/gin-gonic/gin"
)

// AdminAuth 对登录路由之外的请求执行管理员鉴权。
// 实例只保存路由配置;每次请求的身份和令牌均使用局部变量。
type AdminAuth struct {
	loginFullPath string // loginFullPath 唯一免鉴权登录路由的完整路径。
}

// NewAdminAuth 创建鉴权中间件;loginFullPath 应由路由前缀与登录路径拼接。
func NewAdminAuth(loginFullPath string) (*AdminAuth, error) {
	if loginFullPath == "" || !strings.HasPrefix(loginFullPath, "/") {
		return nil, errors.New("login route must be an absolute route path")
	}
	return &AdminAuth{loginFullPath: loginFullPath}, nil
}

// Handle 读取 Bearer 令牌,调用业务层鉴权,成功后将管理员 ID 放入本次请求上下文。
// 登录仅按 POST + 已匹配的完整路由放行;OPTIONS 由前面的 CorsPreflight 终止。
func (a *AdminAuth) Handle(c *gin.Context) {
	c.Header("Cache-Control", "no-store")
	if a == nil {
		respBody := &resp_body.RespBody{}
		respBody.InternalError(&sys_error.InternalError{Cause: errors.New("nil authentication middleware")})
		c.AbortWithStatusJSON(http.StatusOK, respBody)
		return
	}

	if c.Request.Method == http.MethodPost && c.FullPath() == a.loginFullPath {
		c.Next()
		return
	}

	rawToken, err := a.bearerToken(c)
	if err != nil {
		a.reject(c, err)
		return
	}

	administrator := &biz.Admin{}
	err = administrator.Authenticate(c.Request.Context(), rawToken)
	if err != nil {
		a.reject(c, err)
		return
	}

	// 只保存确认后的身份 ID,不将密码摘要或原始 JWT 放入 Gin 上下文。
	c.Set(adminIDContextKey, administrator.ID)
	c.Next()
}

// bearerToken 只从唯一的 Authorization 请求头读取 Bearer 令牌。
// 缺失、重复请求头、方案不匹配或包含多段凭据时均返回 InvalidTokenErr。
func (a *AdminAuth) bearerToken(c *gin.Context) (string, error) {
	values := c.Request.Header.Values("Authorization")
	if len(values) != 1 {
		return "", auth.InvalidTokenErr
	}
	parts := strings.Fields(values[0])
	if len(parts) != 2 || !strings.EqualFold(parts[0], "Bearer") {
		return "", auth.InvalidTokenErr
	}
	return parts[1], nil
}

// reject 按项目业务码返回鉴权错误,同时停止后续中间件和业务处理器。
// AbortWithStatusJSON 不会结束当前 Go 函数,调用方仍须立即 return。
func (a *AdminAuth) reject(c *gin.Context, err error) {
	respBody := &resp_body.RespBody{}
	var databaseError *sys_error.DatabaseError
	switch {
	case errors.Is(err, auth.ExpiredTokenErr):
		respBody.TokenExpiredError()
	case errors.Is(err, auth.InvalidTokenErr):
		respBody.InvalidToken()
	case errors.As(err, &databaseError):
		respBody.DBError(err)
	default:
		respBody.InternalError(&sys_error.InternalError{Cause: err})
	}
	c.AbortWithStatusJSON(http.StatusOK, respBody)
}

bearerToken() 仅接受唯一的 Authorization 头，并用 strings.Fields() 拆为方案名与令牌两段。方案名比较不区分大小写，JWT 内容保留原样；不从 URL 查询参数、Cookie 或请求体中寻找备用令牌。JWT 长度继续由现有解析器限制为最多 4096 字节。

拒绝请求必须调用 c.AbortWithStatusJSON()，然后从当前方法 return。仅返回 JSON 或仅从当前函数 return 都不足以可靠阻止 Gin 的其余处理器；Abort 停止后续链，return 结束当前函数。Gin Context 文档 ↗

中间件设置 Cache-Control: no-store，覆盖鉴权错误和后续受保护接口的响应。未通过鉴权时，不会写入身份 ID，也不会调用后续业务处理器。

读取本次请求的管理员 ID

新增 middleware/admin_context.go，将上下文键和读取函数单独保存，避免控制器重复手写键名和直接进行类型断言。

新增完整文件middleware/admin_context.go 
package middleware

import "github.com/gin-gonic/gin"

// adminIDContextKey 用于保存已经通过鉴权的管理员 ID,避免调用方手写键名。
const adminIDContextKey = "solar_notes.auth.admin_id"

// CurrentAdminID 读取本次请求通过鉴权的管理员 ID。
// 未经过鉴权、值类型不正确或 ID 无效时返回 false,不触发类型断言 panic。
func CurrentAdminID(c *gin.Context) (int64, bool) {
	if c == nil {
		return 0, false
	}
	value, exists := c.Get(adminIDContextKey)
	if !exists {
		return 0, false
	}
	adminID, ok := value.(int64)
	if !ok || adminID <= 0 {
		return 0, false
	}
	return adminID, true
}

需要知道当前操作者的控制器调用 middleware.CurrentAdminID(c)，获得 int64 类型的 ID 和 bool。只有 bool 为 true 才继续使用 ID，并通过形参传给相应业务方法；如果受保护接口意外拿不到身份，应按内部错误结束处理。

c.Set() 保存的是 Gin 请求上下文数据，不会自动添加到 c.Request.Context()。业务层的 context 仍用于取消与超时；身份 ID 应显式传入，不能用请求体中由调用者提供的管理员 ID 代替。

若接口需要把雪花 ID 返回为 JSON，继续使用 strconv.FormatInt(adminID, 10) 转为字符串。仅查询天体状态的控制器不需要额外读取 ID，也会被全局鉴权保护。

在所有路由注册之前安装鉴权

下面的 main.go 示例基于当前工程。登录限流和鉴权例外使用同一个 loginFullPath，它由 v1Prefix + loginPath 生成。

→

→

替换完整文件main.go 
package main

import (
	"SolarNotesAdminAPI/conf"
	"SolarNotesAdminAPI/controller/v1/admin"
	"SolarNotesAdminAPI/controller/v1/planet"
	"SolarNotesAdminAPI/db"
	"SolarNotesAdminAPI/middleware"
	"SolarNotesAdminAPI/snowflake"
	"SolarNotesAdminAPI/validation"
	"errors"
	"log"
	"net/http"

	"github.com/gin-gonic/gin"
)

func main() {
	err := conf.Load()
	if err != nil {
		log.Fatal(err)
	}
	configInstance := conf.Get()

	err = validation.Register()
	if err != nil {
		log.Fatal(err)
	}

	err = db.Connect(configInstance.Database)
	if err != nil {
		log.Fatal(err)
	}

	err = snowflake.InitSnowflake(configInstance.Snowflake.NodeID)
	if err != nil {
		log.Fatal(err)
	}

	router := gin.Default()
	// Tips: 配置可信任代理 IP 或 CIDR 列表,以便在使用 X-Forwarded-For 等头部时正确获取客户端真实 IP 地址
	// 否则获取到的客户端 IP 地址为前置代理的地址,从而导致登录接口访问频率限制失效
	err = router.SetTrustedProxies(configInstance.Service.TrustedProxies)
	if err != nil {
		log.Fatal(err)
	}

	// 为登录路由提供唯一的路径来源,避免限流匹配和注册路径不一致
	v1Prefix := "/v1"
	loginPath := "/admin/login"
	loginFullPath := v1Prefix + loginPath
	loginLimiter := middleware.NewLoginRouteLimit(loginFullPath)
	adminAuth, err := middleware.NewAdminAuth(loginFullPath)
	if err != nil {
		log.Fatal(err)
	}

	bodyLimit, err := middleware.NewRequestBodyLimit(configInstance.Service.MaxRequestBodyBytes)
	if err != nil {
		log.Fatal(err)
	}

	// 先处理跨域头、登录限流和请求体限制;预检结束后再鉴权。
	// 必须在创建路由组、注册任何业务路由之前安装全局鉴权。
	router.Use(
		middleware.CorsHeaders,
		loginLimiter.Handle,
		bodyLimit.Handle,
		middleware.CorsPreflight,
		adminAuth.Handle,
	)

	v1 := router.Group(v1Prefix)
	{
		v1.POST(loginPath, admin.Login)
		v1.GET("/planet/status", planet.ShowStatus)
	}

	server := &http.Server{
		// 开发环境沿用当前监听地址。
		Addr: "0.0.0.0:" + configInstance.Service.Port,
		// TODO: 使用同机 Nginx 部署时,将上一行改为:
		// Addr: "127.0.0.1:" + configInstance.Service.Port,
		Handler:           router,
		ReadHeaderTimeout: configInstance.Service.ReadHeaderTimeout(), // 读取完整请求头的最长时间
		ReadTimeout:       configInstance.Service.ReadTimeout(),       // 读取整个请求(包括请求头和请求体)的最长时间
		IdleTimeout:       configInstance.Service.IdleTimeout(),       // 已完成请求的连接,在等待下一个请求时的最长空闲时间
	}

	err = server.ListenAndServe()
	if err != nil && !errors.Is(err, http.ErrServerClosed) {
		log.Fatal(err)
	}
}

router.Use 必须早于路由组创建和路由注册。 Gin 会把当时的中间件链合并到路由；不要先注册接口，再补装鉴权。后续在这之后新增的 /v1、/v2 等路由都会默认受到保护。

这里使用全局中间件，因此不需要在 v1.GET("/planet/status", ...) 上再单独添加一次鉴权，也不需要给每个新 API 重复注册。全局登录限流保持原位置，不要在登录路由上重复挂载。

这个顺序保留原有响应优先级：登录限流和请求体错误可能先于鉴权返回；请求体超限不会进入鉴权或业务处理器。未匹配的路径也可能先得到鉴权错误；身份有效后，才继续由 Gin 处理未匹配路由。Gin 自身的路由重定向不执行目标业务处理器，客户端随后访问目标路由时仍需通过鉴权。

07 / TOKEN STATE

退出、改密和重新登录如何影响令牌

数据库当前状态持有旧 JWT 的请求原因
token_hash 仍为该 JWT 的摘要JWT 也有效时允许继续。签名、时效和数据库摘要均通过。
退出后 token_hash 被清空有效期内也返回 20004。数据库已不再允许使用该令牌。
重新登录后写入新 JWT 的摘要旧 JWT 返回 20004，新 JWT 可以通过。一个账号只保存一个当前摘要。
改密时同步清空 token_hash旧 JWT 返回 20004。改密业务撤销了原登录状态。
管理员记录被删除返回 20004。已不存在可验证的管理员身份。

鉴权中间件只读取状态。后续退出接口需要提交清空 token_hash 的更新；改密处理应在同一条 UPDATE 或同一事务中更新密码摘要并清空令牌摘要。仅修改密码字段，不会自动撤销一个尚未过期且摘要仍匹配的 JWT。

现有登录业务每次成功登录都会覆盖摘要，因此这套实现对应同一账号只保留一枚当前令牌。同一枚令牌被复制到多个客户端时，清空摘要会使它们随后执行的鉴权均失败。

撤销针对后续读取到新状态的鉴权检查。 已经通过鉴权、正在执行业务的请求不会因摘要后来被清空而自动停止或回滚。需要严格协调并发登录、改密或退出的业务操作时，应在这些业务方法中使用相应的事务和条件更新；中间件本身不提供跨请求的事务锁。

JWT 的 exp 仍由后端解析器检查，数据库的 token_hash 用于确认当前登录状态。两项检查各自承担职责，不需要为本方案新增 token 明文列或过期时间列。
