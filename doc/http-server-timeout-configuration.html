HTTP 服务超时
配置实现方案

将请求头、整个请求和连接空闲超时写入配置，并在启动时完成校验与单位转换。

service 配置段整数秒启动时校验仅文档 · 手动实施

配置文件负责提供时长，配置层负责校验和转换，HTTP 服务负责应用。 开发环境的监听地址及可信代理使用方式沿用现有设计。

代码块可单独展开和复制。
01 / OVERVIEW

配置哪些时间？

配置项示例值用途
read_header_timeout_seconds5 秒读取请求头允许的最长时间。
read_timeout_seconds15 秒读取整个请求（包括请求头和请求体）允许的最长时间。
idle_timeout_seconds60 秒保持连接时，等待下一个请求的最长空闲时间。

数值均使用整数秒。上表是便于开发的示例，不是必须采用的固定值；实际值应根据网络情况和接口需求调整。

ReadTimeout 针对请求读取阶段，并不是数据库操作或业务处理的执行时限；IdleTimeout 也不是 JWT 的有效期。官方定义见 Go 标准库 http.Server。

02 / CONFIGURATION

扩展服务配置并接入校验

在已有的 conf.Service 中新增三个字段和对应方法，继续使用 Service 持有端口与可信代理，不新增独立配置对象。

以下规则是本方案的约定：三个值必须是可转换为 time.Duration 的正整数秒；read_timeout_seconds 不得小于 read_header_timeout_seconds。后者不是 Go 的强制要求，而是为了让总读取时间与请求头时间的含义更直观；两个值相等时，较慢的请求头可能几乎耗尽请求体的读取时间。

替换完整文件conf/service.go
package conf

import (
	"errors"
	"time"
)

// maxServiceTimeoutSeconds 是转换为 time.Duration 时不会溢出的最大秒数。
const maxServiceTimeoutSeconds int64 = (1<<63 - 1) / int64(time.Second)

// Service 服务相关配置。
type Service struct {
	Port                     string   `yaml:"port"`                        // Port 服务监听端口。
	TrustedProxies           []string `yaml:"trusted_proxies"`             // TrustedProxies 可信代理 IP 或 CIDR 列表。
	ReadHeaderTimeoutSeconds int64    `yaml:"read_header_timeout_seconds"` // ReadHeaderTimeoutSeconds 读取请求头的最长时间，单位秒。
	ReadTimeoutSeconds       int64    `yaml:"read_timeout_seconds"`        // ReadTimeoutSeconds 读取整个请求的最长时间，单位秒。
	IdleTimeoutSeconds       int64    `yaml:"idle_timeout_seconds"`        // IdleTimeoutSeconds 等待下一个请求的最长空闲时间，单位秒。
}

// validate 校验 HTTP 服务超时配置；应在配置加载时调用。
func (s *Service) validate() error {
	if s.ReadHeaderTimeoutSeconds <= 0 || s.ReadHeaderTimeoutSeconds > maxServiceTimeoutSeconds {
		return errors.New("service.read_header_timeout_seconds 必须是有效的正秒数")
	}
	if s.ReadTimeoutSeconds <= 0 || s.ReadTimeoutSeconds > maxServiceTimeoutSeconds {
		return errors.New("service.read_timeout_seconds 必须是有效的正秒数")
	}
	if s.IdleTimeoutSeconds <= 0 || s.IdleTimeoutSeconds > maxServiceTimeoutSeconds {
		return errors.New("service.idle_timeout_seconds 必须是有效的正秒数")
	}
	if s.ReadTimeoutSeconds < s.ReadHeaderTimeoutSeconds {
		return errors.New("service.read_timeout_seconds 不得小于 read_header_timeout_seconds")
	}
	return nil
}

// ReadHeaderTimeout 返回读取请求头的最长时间；应在配置校验通过后调用。
func (s *Service) ReadHeaderTimeout() time.Duration {
	return time.Duration(s.ReadHeaderTimeoutSeconds) * time.Second
}

// ReadTimeout 返回读取整个请求的最长时间；应在配置校验通过后调用。
func (s *Service) ReadTimeout() time.Duration {
	return time.Duration(s.ReadTimeoutSeconds) * time.Second
}

// IdleTimeout 返回等待下一个请求的最长空闲时间；应在配置校验通过后调用。
func (s *Service) IdleTimeout() time.Duration {
	return time.Duration(s.IdleTimeoutSeconds) * time.Second
}

将服务校验加入现有调用链

在 conf/config.go 中，只替换现有的 Config.validate() 方法；其他配置、加载和规范化代码保留。该方法会在原有数据库、JWT 等校验前检查服务超时。

仅替换此方法conf/config.go · Config.validate()
// validate 本方法用于检查配置文件中的配置项值是否合法
func (c *Config) validate() error {
	err := c.Service.validate()
	if err != nil {
		return err
	}

	err = c.Database.validate()
	if err != nil {
		return err
	}

	err = c.JWT.validate()
	if err != nil {
		return err
	}

	err = c.Asset.validate()
	if err != nil {
		return err
	}

	err = c.Storage.validate()
	if err != nil {
		return err
	}

	err = c.Snowflake.validate()
	if err != nil {
		return err
	}

	return nil
}

此方案不为缺失项设置隐式默认值。字段缺失、留空、为零、为负数，或转换成 time.Duration 时会溢出，都会导致配置加载失败并阻止服务启动。Go 标准库对部分零值有回退语义；这里显式拒绝零值是项目配置策略。

04 / SERVER

从配置创建 HTTP 服务

使用 http.Server 替换原来的 router.Run()。下面是基于当前工程的完整 main.go 示例；保留了现有路由、限流器、可信代理和开发监听地址。将来按现有部署计划使用同机 Nginx 时，修改 server.Addr 中的地址即可。

替换完整文件main.go
package main

import (
	"SolarNotesAdminAPI/conf"
	"SolarNotesAdminAPI/controller/v1/admin"
	"SolarNotesAdminAPI/db"
	"SolarNotesAdminAPI/middleware"
	"SolarNotesAdminAPI/snowflake"
	"SolarNotesAdminAPI/validation"
	"errors"
	"log"
	"net/http"

	"github.com/gin-gonic/gin"
)

// main 加载配置与依赖，注册路由并启动带超时的 HTTP 服务。
func main() {
	err := conf.Load()
	if err != nil {
		log.Fatal(err)
	}
	configInstance := conf.Get()

	err = validation.Register()
	if err != nil {
		log.Fatal(err)
	}

	err = db.Connect(configInstance.Database)
	if err != nil {
		log.Fatal(err)
	}

	err = snowflake.InitSnowflake(configInstance.Snowflake.NodeID)
	if err != nil {
		log.Fatal(err)
	}

	router := gin.Default()
	// Tips: 配置可信任代理 IP 或 CIDR 列表,以便在使用 X-Forwarded-For 等头部时正确获取客户端真实 IP 地址
	// 否则获取到的客户端 IP 地址为前置代理的地址,从而导致登录接口访问频率限制失效
	err = router.SetTrustedProxies(configInstance.Service.TrustedProxies)
	if err != nil {
		log.Fatal(err)
	}
	router.Use(middleware.Cors())

	v1 := router.Group("/v1")
	loginLimiter := middleware.NewLoginRateLimiter()

	{
		v1.POST("/admin/login", loginLimiter.Handle, admin.Login)
	}

	// 使用显式 HTTP 服务，以便读取已校验的超时配置。
	server := &http.Server{
		// 开发环境沿用当前监听地址。
		Addr: "0.0.0.0:" + configInstance.Service.Port,
		// TODO: 上线使用同机 Nginx 时，将上一行替换为：
		// Addr: "127.0.0.1:" + configInstance.Service.Port,
		Handler:           router,
		ReadHeaderTimeout: configInstance.Service.ReadHeaderTimeout(),
		ReadTimeout:       configInstance.Service.ReadTimeout(),
		IdleTimeout:       configInstance.Service.IdleTimeout(),
	}

	err = server.ListenAndServe()
	if err != nil && !errors.Is(err, http.ErrServerClosed) {
		log.Fatal(err)
	}
}

ListenAndServe() 会阻塞直到服务停止或启动失败；http.ErrServerClosed 表示服务正常关闭。此示例只识别这一结果，不会自动为程序增加优雅关闭流程。

若请求头读取超时，连接可能在进入 Gin 和 Controller 前结束，客户端不一定收到项目的 JSON 响应体。前端应按网络异常或超时处理，而不是假设每次都能收到业务码。

05 / VERIFICATION

测试与实施检查

可将以下测试保存为 conf/service_timeout_test.go。它使用合成数据，不读取开发密钥、不连接数据库，覆盖 YAML 字段、时间转换、启动校验链、零值、负数、溢出及两个读取时间之间的约束。

可选测试文件conf/service_timeout_test.go
package conf

import (
	"bytes"
	"encoding/base64"
	"strings"
	"testing"
	"time"

	"go.yaml.in/yaml/v3"
)

// TestServiceTimeoutValidation 验证超时配置的有效值、边界及相互关系。
func TestServiceTimeoutValidation(t *testing.T) {
	const maximum int64 = (1<<63 - 1) / int64(time.Second)
	cases := []struct {
		name   string // name 场景名称。
		header int64  // header 请求头读取超时秒数。
		read   int64  // read 整个请求读取超时秒数。
		idle   int64  // idle 空闲连接超时秒数。
		valid  bool   // valid 表示是否应通过校验。
	}{
		{"示例值", 5, 15, 60, true},
		{"读取时间等于请求头时间", 5, 5, 60, true},
		{"最大可转换秒数", 1, maximum, maximum, true},
		{"请求头超时为零", 0, 15, 60, false},
		{"请求头超时为负", -1, 15, 60, false},
		{"请求超时为零", 5, 0, 60, false},
		{"空闲超时为零", 5, 15, 0, false},
		{"空闲超时为负", 5, 15, -1, false},
		{"请求头超时溢出", maximum + 1, maximum + 1, 60, false},
		{"请求超时溢出", 5, maximum + 1, 60, false},
		{"空闲超时溢出", 5, 15, maximum + 1, false},
		{"请求超时小于请求头超时", 10, 5, 60, false},
	}

	for _, tc := range cases {
		service := &Service{
			ReadHeaderTimeoutSeconds: tc.header,
			ReadTimeoutSeconds:       tc.read,
			IdleTimeoutSeconds:       tc.idle,
		}
		err := service.validate()
		if (err == nil) != tc.valid {
			t.Errorf("%s：valid=%v, err=%v", tc.name, tc.valid, err)
		}
		if err == nil && (service.ReadHeaderTimeout() <= 0 || service.ReadTimeout() <= 0 || service.IdleTimeout() <= 0) {
			t.Errorf("%s：转换后的超时时长必须为正", tc.name)
		}
	}
}

// TestServiceTimeoutYAMLBinding 验证严格模式下的 YAML 字段绑定与秒数转换。
func TestServiceTimeoutYAMLBinding(t *testing.T) {
	const input = `service:
  port: "4060"
  trusted_proxies: []
  read_header_timeout_seconds: 5
  read_timeout_seconds: 15
  idle_timeout_seconds: 60
`
	var config Config
	decoder := yaml.NewDecoder(strings.NewReader(input))
	decoder.KnownFields(true)
	if err := decoder.Decode(&config); err != nil {
		t.Fatal(err)
	}
	if err := config.Service.validate(); err != nil {
		t.Fatal(err)
	}
	if config.Service.Port != "4060" || len(config.Service.TrustedProxies) != 0 {
		t.Fatal("既有服务配置绑定错误")
	}
	if config.Service.ReadHeaderTimeout() != 5*time.Second ||
		config.Service.ReadTimeout() != 15*time.Second ||
		config.Service.IdleTimeout() != 60*time.Second {
		t.Fatal("超时配置的单位转换错误")
	}
}

// TestConfigValidatesServiceTimeouts 验证现有 Config 校验链会执行服务超时校验。
func TestConfigValidatesServiceTimeouts(t *testing.T) {
	config := &Config{
		Service: Service{
			ReadHeaderTimeoutSeconds: 5,
			ReadTimeoutSeconds:       15,
			IdleTimeoutSeconds:       60,
		},
		Database:  Database{Host: "localhost", Port: "3306", User: "test", Password: "test", Name: "test"},
		JWT:       JWT{Issuer: "test", Audience: "test", ExpireSeconds: 604800, Secret: base64.StdEncoding.EncodeToString(bytes.Repeat([]byte{9}, 32))},
		Asset:     Asset{BaseURL: "https://example.com"},
		Storage:   Storage{RootDir: "/tmp/solar-notes-test"},
		Snowflake: Snowflake{NodeID: 1},
	}
	if err := config.validate(); err != nil {
		t.Fatal(err)
	}
	config.Service.ReadTimeoutSeconds = 4
	if err := config.validate(); err == nil {
		t.Fatal("Config.validate 应拒绝无效的服务超时配置")
	}
}

超时控制不限制请求体的字节数：登录请求体大小仍需要单独限制。若后续增加大文件上传或慢速流式接口，服务级 ReadTimeout 会影响这些接口，应根据实际需求重新评估；前置代理也需要按部署情况配置自己的超时。
