编辑天体标题与简介

管理员从列表打开编辑抽屉，保存时提交天体 ID、打开抽屉时读到的原文，以及本次想保存的内容。服务端锁定该 ID 对应的一行，核对原文后更新标题和简介。成功响应可直接替换前端列表中的这一行。

前后端编辑契约 · 天体管理原型 · 现有书籍编辑实现文档

请求与响应

沿用管理员鉴权，携带 Authorization: Bearer <access_token>，请求体为 application/json。下面用只改标题的场景说明两个对象的用途。简介仍随 expected 和 target 一起提交；目标标题的首尾空格在保存前去除。

planet.id 使用正 int64 范围内的十进制字符串。响应中的 id 和 name 取自已保存的记录。编辑同样适用于列表中的历史天体，如 Pluto。请求只声明可编辑的两项，模型的写入白名单也只含 title 和 intro。

分别定义原文与目标值的校验

字段Go 绑定与校验语义
planet、expected、target三个必填对象。即使只修改标题或简介，也要提交两项原文和两项目标值。
planet.id用 json:"id,string" 解码，再用 gt=0 校验。裸 JSON 数字、空串、非整数、负数、零及超出 int64 上限的值均返回 10101。
expected.title、expected.intro用 *string 区分缺失或 null 与显式空串。两项都必须是字符串；原样保留历史空串、首尾空白和超出新上限的旧值，供数据库原文比较。
target.title、target.intro在 JSON 解码时用 jstext.TrimSpace 修剪，再由 Gin 校验。标题接受 1–20 个 Unicode 码点，简介接受 1–150 个；纯空白、缺失、null 和非字符串返回 10101。内部空白和换行保留。

例如历史标题为 " Sun "，前端原样放进 expected.title 才能匹配。若把同一文本放进 target.title，落库值为 "Sun"。如果同一条记录的历史简介为空，管理员这次也要补齐目标简介，原文仍提交空串。EditText 仅用于两项目标值，修剪规则复用 jstext.TrimSpace。

在同一个事务中锁定、比对和更新

为 model.Planet 增加 Update(ctx, expectedTitle, expectedIntro)。接收者携带主键和修剪后的目标值。沿用书籍编辑的 READ COMMITTED 事务和 SELECT ... FOR UPDATE：按主键取得最新记录，行锁持续到提交或回滚。方法只访问 planet 表，现有主键即可定位，数据库无需增加字段或索引。

按此顺序判断操作与结果
按 ID 查无记录返回现有 model.PlanetNotFoundErr，业务码 20102。
任一原文与锁定记录不符返回 20103。即使另一个管理员已保存完全相同的目标，也要先报告快照失效。
原文匹配，两个目标值均等于当前值跳过 SQL UPDATE，提交只做了锁定读取的事务，成功返回该行。
原文匹配，至少一个目标值有变化只更新这行的标题和简介，在事务内回读保存结果；提交成功后才回填接收者。执行或提交出错沿用数据库错误处理。

在 Go 中用字符串 != 逐字节比较原文，大小写、尾随空格和 Unicode 组合形式的差异都能识别。两位管理员分别改标题和简介时，后取得锁的一方也必须核对两个原值。这里检查的是这两项的当前值；若期间曾修改又恢复为相同原文，本契约允许保存。

联调与验收

在 Postman 的 Authorization 中选择 Bearer Token，使用已登录管理员的令牌。先调用 GET /v1/planet/list 取得测试记录，原样复制两项原文及字符串 ID，再将第一个示例作为 JSON 请求体提交。项目用 HTTP 200 承载业务结果，页面以响应体的 code 决定如何处理。

场景核验要点
只改简介，然后编辑一条历史名称记录返回 200，以 ID 替换对应列表项；标题与简介取已保存值，ID 和 name 保留。编辑历史名称同样成功。成功后无需复检天体创建状态。
目标含首尾空格、换行或 BOM；再试纯空白及长度边界先修剪再计数。20 个码点的标题和 150 个码点的简介可保存；分别多一个或修剪后为空返回 10101。可用非 BMP 字符验证每个 Unicode 码点计一项。
原文带空白、是历史空串，或超过新长度上限精确提交原文并给出合法目标可以修正历史数据。删掉原文的空格会得到 20103。省略原文字段、传 null、传非字符串或传裸数字 ID 返回 10101。
原文匹配，目标修剪后与原值相同返回 200 及完整的当前行。观察事务仅锁定读取和提交，跳过 UPDATE。
两人从同一份原文分别修改标题、简介；或两人提交相同的新目标先提交的更改成功，另一方返回 20103。前端保留草稿，重读列表，经管理员核对后使用新快照再提交。
有效的正整数 ID 对应的记录已不存在返回 20102 和空 data；关闭失效记录的编辑抽屉，刷新 list 与 status。书籍接口引用缺失天体时原业务码和提示依旧可用。
请求夹带 name，或天体已关联书籍用合法请求其余字段保存后，核对返回和库中 name 与编辑前一致；书籍的 planet_id 保持相同。
鉴权失败、数据库操作失败或客户端等待响应超时过期令牌走 20003，无效令牌走 20004；数据库错误走 10201，内部错误走 500，错误 data 均为 {}。写请求超时后先重读列表核对是否已保存，再决定是否重新提交。
